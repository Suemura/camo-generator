# ドキュメント同期と独立レビュー

コード変更または複数ファイル変更の完了時に適用する。単一ファイルの軽微な typo 修正は対象外。

## docs-sync を先に起動する変更

- ユーザー向け機能・エクスポート・URL・制限値。
- 開発コマンド・ビルド・デプロイ構成。
- `.agents/`・`.claude/`・`.codex/`・`tools/agent-harness/` のハーネス。
- ディレクトリ構造・テスト方針。
- 生成手法変更で `docs/01-tech-verification.md` への判断の追記が欠けている場合。

内部リファクタ、バグ修正、依存更新、テスト追加だけでは起動しない。ただし上記の変更を伴う場合は対象。一般の変更ログはコミットと PR に書く。

## 独立レビューの二本立て

- PR を作るタスク: PR 後の pr-reviewer → pr-comment-resolver が担当する。PR 前の reviewer による重複フルレビューは不要。
- PR を作らないタスク: reviewer が担当する。Fail があれば修正して再レビューする。修正ループは最大3回。その後は残る指摘と未完了を報告する。
- 独立レビューは実装担当とは別のコンテキストで行う。差分と完了条件に照らして根拠を返し、未確認を Pass 扱いしない。

## 手渡す情報

依頼時に変更概要、変更ファイル一覧、`git diff <base>...HEAD --stat`、未コミットがあれば `git status --short`、完了条件、実行済み検証と結果を渡す。生成結果の影響、スナップショット更新の有無、目視確認のシード・スケールも明記する。

受け手はその差分と直接の参照元・参照先から読み始める。既に証拠のあるテストを機械的に再実行せず、新しい変更や未解決の疑義がある場合に追加検証する。
