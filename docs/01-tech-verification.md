# フェーズ1: 技術検証メモ

## プロトタイプ

`prototype/index.html` — 依存ライブラリなしの単一 HTML。ブラウザで直接開けるほか、Artifact として公開済み。

## 生成アプローチ

すべて **シード付きハッシュベースの値ノイズ（value noise）+ fBm（多オクターブ合成）+ ドメインワープ** で構成。乱数は `Math.random` を使わず座標ハッシュで決定的に生成するため、同一シード → 同一結果が保証される。

### 形状と色の分離

形状はスカラー場（Float32Array）として生成し、分位点（quantile）で閾値を決めて色スロットに割り当てる。この構造により:

- 色の面積比がパレットに依存せず一定に保たれる
- パレット差し替えは再着色のみで即時反映できる

### パターン別の手法

- **ウッドランド (M81)**: 横長異方性（X周波数 < Y周波数）+ 強ドメインワープの fBm を3層重ね。黒層はスカラー場の「等高線バンド」（分位点0.46〜0.55の帯）で枝状の細長い形状を再現
- **マルチカム / OCP**: 低周波場をタン→ペールグリーン→オリーブの連続グラデーションにマップした地に、茶斑（コアはダークブラウン）+ 高周波の明色小斑・暗色小斑を重ねる
- **デジタル系 (MARPAT / AOR1 / AOR2 / UCP)**: セルグリッド上で低周波（大領域）+ 高周波(エッジのギザつき)を合成し、指定面積比の分位点で N 値量子化

## v2 での改善（フィードバック反映）

初期実装は精度不十分（全パターン同系ロジック・実物特徴の欠如）だったため、以下を実施:

1. **目視反復ループの構築** — `camo.js`（生成コア、browser/node 共用）+ `render.mjs`（Node で PNG 出力）で、生成結果を実物参照画像（Wikimedia の M81 / MARPAT / UCP 布地写真）と目視比較しながら調整。`node render.mjs <outdir> <seed>` で全プリセット出力
2. **ウッドランド黒層の作り直し** — 等幅の等高線バンド → 「可変太さの枝」。芯線フィールドからの距離を別ノイズで変調した太さと比較。テーパーで自然に途切れ、所々で太る
3. **デジタル系の後処理追加** — 実物観察に基づき (a) マクロ島 + メソ斑の2スケール構造、(b) 境界ディザ（隣接異色セルへの確率スワップでギザギザ食い込み）、(c) 境界近傍限定のスペックル（1セル飛び地、低周波マスクで密度ムラ）
4. **デジタル系のパターン別差別化** — 実系譜（CADPAT→MARPAT→AOR/UCP は同族）どおり共通エンジンだが、面積比・マクロ/メソ周波数・伸長方向（UCP は横伸長）・スペックル色ペアをパターン別に定義
5. **マルチカム/OCP をスコープアウト** — グラデーション地の再現精度が低いため一旦除外。フェーズ2以降で再挑戦

参考実装調査: [CAMO](https://github.com/ecsplendid/CAMO)（fBm 閾値方式、現行実装と同系）、[camogen](https://github.com/glederrey/camogen)（ポリゴン再帰分割 + color bleed 方式。有機系の代替アプローチとして候補）

## v3: 自己改善ループ（10周）

実物参照画像（Wikimedia の布地写真・スウォッチ: M81 / MARPAT / UCP / AOR1 / AOR2）を取得し、
「レンダ → 参照と目視比較 → 採点 → 調整」を10周実施。主な技術的成果:

- **勾配正規化の等高線バンド**（M81黒・ツイッグ共通）: `|field−level| < |∇field|×widthPx` で枝の太さをピクセル単位制御。ノイズ勾配の暴れによる巨大な瘤・マーブル化を解消
- **勾配マスク**: 極値近傍（勾配小）を除外し、等高線由来の「閉ループ（輪っか）」を抑制。分位0.15。強すぎる(0.35)と枝が破線化するトレードオフあり
- **ツイッグシステム**: AOR2/MARPAT 特有の蛇行する暗色細枝。伸長付き等高線バンドをセル量子化
- **粒度の実物合わせ**: デジタル系は当初の3〜4倍細かい粒度が正解（AOR系は特に細粒）。UCP はセル大きめ(cell 5)+横伸長
- **面積比・パレットの実物準拠化**

### 自己評価（100点満点、実物との目視比較）

目標の90には未到達（10周で打切り）。90到達には現行のノイズ閾値方式の限界があり、

## v5: ハイブリッド統合 + リファレンス並列表示

- UI: 従来/新手法をプリセットとして並置し比較可能。各パターン選択時に**実物リファレンス画像**（Wikimedia Commons、420px縮小 data URI 埋め込み）を生成結果の隣に表示

- 候補A（ポリゴン分割）は実物模倣では不採用。フェーズ2の「オリジナル迷彩生成」機能候補として experimental/ に保持

### 90点未到達の要因分析

実物迷彩は「デザイナーが意図配置した固定図案」であり、統計的手続き生成との残差は:
1. **形状の意図性** — M81 の個々の斑・黒枝は手描きデザイン。確率的生成では「らしさ」は出るが「同じ設計言語」にならない
2. **図案の全体構成** — 実物は視距離設計(近距離ディテール+遠距離ブロブ)が計算されている

90+ に届く候補: ①実物図案の統計(斑サイズ分布・隣接頻度)をフィッティングする最適化 ②実パターンのトレース素材をタイル+変形合成 ③拡散モデル等のML。いずれもフェーズ2以降の大きな投資判断。

## v7: Image Quilting によるウッドランド突破

既存実装調査（Substance Designer / Blender のカモフラ生成レシピ）の結論: プロツールの定番も「ノイズ→閾値→歪み(Warp/Slope Blur/Distortion)」系で、当プロジェクトが到達済みの手法族。この族では M81 の「デザインされた図案感」に限界（~75点）。

**採用手法: Image Quilting (Efros & Freeman, SIGGRAPH 2001)**
- Wikipedia の US Woodland ベクタ画像（米政府図案=パブリックドメイン）を 4値インデックスマップ化し RLE 埋め込み（25KB）
- ブロック(ソース基準 ~200px)をオーバーラップ付きで配置。候補36個から「オーバーラップ不一致(正規化) + 色多様性ペナルティ(黒欠乏を重罰)」最小を選択、境界は動的計画法の最小誤差シームで縫合
- ミラー(H/V)で配置バリエーション増加。シードで全配置が決定的に変化
- **局所形状が実物の設計言語そのもの**のため、斑の指状突起・黒枝の鹿角形状が原理的に再現される
- 失敗と対策: 単純な誤差最小化は「平坦ブロック同士のマッチ」に退化 → ブロック色構成を実物面積比に近づける多様性ペナルティで解消

自己評価（ユーザー較正スケール）: **M81 クイルト 85**。512生成 ~60ms、2048 ~300ms。
プリセットは「従来 / 新手法(形状文法) / 新手法(クイルト)」の3方式並置。

制約・今後: ①ソース由来のため「US Woodland 風」専用（汎用形状生成ではない）②大伸長時は nearest サンプリングのエッジ段差（要スムージング）③同手法は AOR2(SVGソースあり)・UCP にも展開可能。

### v8: ブロブパッチ合成への全面変更

矩形グリッド quilting はユーザーレビューで「ブロックの組み合わせ感・カクカク」と指摘。直線シームは平坦色領域の不一致部で必ず露出する構造的問題（ドメインワープでの隠蔽は櫛歯化・帯状化で失敗）。

→ **ブロブパッチ合成**（Graphcut Textures の簡略版）に変更:
- ベースを全面ランダムクロップで敷き、その上に**有機輪郭パッチ**（角度ノイズで半径変調した星型マスク、r(θ) = R·(0.62+0.55·fbm(θ周期))）を貼り重ねる
- パッチ候補48個から「境界リング上の不一致 + キャンバス全体の不足色を動的補正する多様性ペナルティ」最小を選択
- ミスマッチ境界も**有機曲線の新たな迷彩境界**として自然に見える（直線・矩形が構造的に存在しない）
- ミラーは座標折返し(reflect)でソース範囲外も安全に参照

自己評価: M81 ブロブパッチ **85**（丸み・図案言語・配色バランス、3シード+scale1.3確認）。512生成 380〜600ms。

### v9: 広範囲ソース + 仕上げループ（8周）

1. **ベンチマーク/ソース交換** — Commons の広範囲 M81 スウォッチ（800×685、旧ベクタの約2倍の視野）に交換。ベンチマーク表示・クイルトソース・既定パレット（#9c8f6f/#4c5f49/#5f5345/#3a3e3d）・面積比（24/27/33/16）を同一画像から導出し、生成と参照の見かけスケールを一致させた
2. **鏡映アーティファクト修正** — reflect折返しがパッチ内に入ると蝶々状の左右対称が出る → パッチ中心相対サンプリング + 折返し不要なソース範囲選択に変更
3. **微小フラグメント除去** — パッチ境界が生む実物に無い小欠片（<110px相当）を近傍多数色へ併合。初回実装は BFS 早期打切りで偽成分を量産するバグ → 完全走査に修正
4. **パッチ大型化**（R 150→185/k、被覆2.2x）— 長い黒枝ネットワークが切断されず保存

検証: 4シード × scale 0.7/1.0/1.3/1.55。自己評価（ユーザー較正）: **M81 クイルト 90**。512生成 170〜340ms。
→ ユーザー評価 **88**。残指摘: 縮尺変更時にパッチ境界で色が急変する箇所。

### v10: 境界露出・鏡映の根絶

1. **境界リング誤差の重み強化**（score = ring×2.6 + diversity×1.2、候補60）+ リング誤差 >0.30 ならパッチ中心を再抽選（最大3回）— 「貼っても境界線が出ない場所」を探してから貼る
2. **ベース層の廃止** — 高スケール時にベース敷きがソース折返しを強制し鏡映模様が出ていた → 未塗布センチネル(255)から全面をパッチのみで被覆。境界リング誤差は塗布済みセルのみで評価
3. **ホール充填** — 未塗布残りはその位置中心の追加パッチで充填（未塗布セルのみ上書き）

検証: seed 680219(ユーザー再現)/1234/777/211025 × scale 1.0/1.3/1.8 — 境界急変・鏡映とも解消。512生成 320ms〜1.2s(高スケール時)。
→ ユーザー再指摘: シェイプがパッチ縁で「バサッと」切断される箇所が残存（scale 1.5 で顕著）。

### v11: 領域成長型シーム（切断面の構造的排除）

リング誤差最小化では「シェイプの途中切断」を完全には防げない（続きの無い切り口が円弧/直線として残る）。
→ パッチ貼付を **領域成長型シーム** に変更:
- コア(0.55R)のみ無条件貼付し、そこから BFS で外側へ拡張
- 拡張できる条件は「新値=旧値（継ぎ目不可視）」「新値=隣接塗布済み新値（新シェイプ自身の連続）」「未塗布」のみ
- → 色の遷移が必ず**どちらかの画像の実シェイプ輪郭上**で起こる。切断面が構造的に発生しない（グラフカットの単純化に相当）

検証: seed 1234×scale1.5(ユーザー再現) / 680219×1.8 / 777×1.0 / 211025×1.3 — 切断面消滅。

### v12: 外部レビュー(Gemini)の切り分けと反映

- **不採用(前提誤解)**: fBm多重化・ベクターディスプレイスメント・色別ノイズスケール・シャープ閾値の提案 — 全て「従来手法」で実装済みの手法族で、当プロジェクトで上限(ユーザー評価60)を実証済み。現行クイルトはノイズ生成ではなく実物図案サンプリングのため適用対象外
- **採用(観察は正しい)**:
  1. 「滑らかすぎ/描かれた感」→ 実原因は仕上げ多数決フィルタがソース由来の微細輪郭を削っていた。平滑化をスケール条件付き最小限に(k≈1では無加工)
  2. 「塊サイズ均一」→ 実原因は多様性ペナルティが「全色入り中庸ブロック」を優遇。パッチ径分散を拡大(0.7〜1.3R)し、25%を「マクロパッチ」(1.6〜2.1R・多様性緩和)として実物の大判掃引領域を導入
- 付随修正: ホール充填も候補選択+領域成長型に統一(充填部の切断面を排除)

### v13: 直線的境目・チェッカー模様の解消

ユーザー指摘(scale 2): ①緑/茶の境目が直線的・機械的 ②市松状ノイズ。

- **①の根因 = 半径クリップ**: 領域成長シームは新シェイプの続きを塗るが、ブロブ半径で成長を打ち切っていたため、大きなシェイプが半径の滑らかな弧で切り落とされていた → 「新シェイプの連続」はパッチ半径を超えて自然な輪郭まで成長を許可(bbox 1.9R 上限、コアは0.45Rに縮小)。ブロブ外では「一致 or 連続」のみ塗布
- **②の根因 = 縮小エイリアス**: scale≥1.5 で k>1.4 の nearest サンプリングが細部を市松状に破壊 → **多数決ミップマップ**(2×2の4値多数決で段階縮小、k∈[0.7,1.4] になるレベルからサンプル)

検証: 1234×2.0(ユーザー再現) / 1234×1.5 / 777×1.0 — 両症状消滅。

### v14: 高スケール時の微小点除去

フラグメント除去閾値がスケール反比例(110/scale²)のため、scale>2 で閾値が~20px²まで縮み微小点が残存 → 画面基準の絶対下限 `max(70, 110/scale²)`(512基準px²)を導入。scale≤1 は挙動不変。検証: 1234×2.35(ユーザー再現)で点消滅、777×1.0 で回帰なし(出力バイト一致)。

## v15: プリセット統一 + AOR クイルト化（フェーズ1 精度確定版）

## v15: シームレスタイリング（フェーズ3、2026-09-03）

### 目的

生地印刷・3D テクスチャ用途の前提として、出力を上下左右に並べても継ぎ目が見えないトーラス生成を全手法に導入する。`generate(key, w, h, seed, scale, { tileable })`、既定 `true`。`tileable: false` はフェーズ1 と完全同一の出力（全 6 プリセットのハッシュ一致を確認）。

### 実装

- **共通**: `wrapI`（座標のトーラス折返し）/ `wrapD`（最短差分）を追加
- **クラスタ成長（MARPAT / UCP）**: `growCluster` の近傍 push・同色近傍カウント・ドリフト方向と重心更新を最短差分で計算。境界ディザ・スペックルは全セルを対象にラップ近傍で処理。セル数を `round(w/cellPx)` にして端の半端セルを排除（セル幅は最大 ±1px 不均一になるが境界は揃う）
- **クイルト（M81 / AOR1 / AOR2）**: キャンバスをトーラスとして扱う。候補スコアリングの境界リング・穴埋め・多数決フィルタ・フラグメント除去をすべてラップ近傍で処理。ソース参照は非ラップの相対座標のまま（鏡映対策を維持）
- **`pasteBlobTorus`**: トーラス専用の貼付ルーチンを分離。2 点が重要:
  1. 訪問管理をパッチローカル座標ではなく **キャンバス座標**で行う。M81 のパッチ半径はキャンバス幅の最大 0.8 倍あり、トーラス上で自分自身と重なる。ローカル管理だと同一ピクセルを 2 つの相対座標から別サンプルで塗ろうとし、成長条件が「不一致」判定になって前線が止まり、継ぎ目が直線の切断面になった
  2. 座標丸めは `Math.floor`。`|0` は負側で 0 方向に切り捨てるため x=0 の列が 2 重サンプルになる（同じく成長停止の原因）

### 検証

- 継ぎ目指標: 右端→左端 / 下端→上端 の色変化率 ÷ 内部の隣接変化率（1.0 なら継ぎ目は内部と区別不能）。成長系はセルグリッド単位で測る（ピクセル単位だと cellPx 倍に膨れる）。1 列の指標は分散が大きいので 3 シード平均で判定
- 結果（512×512、scale 1.0、3 シード平均）: 全プリセット 0.6〜1.8。`tileable:false` の woodland は 3 超（指標の妥当性確認）
- 目視: `node tools/render.mjs <out> <seed> <scale> --tile` の 2×2 タイル 6 種 × 複数シード・スケール（0.7 / 1.0 / 1.5 / 2.0）で継ぎ目視認不可。既知アーティファクト（ブロック感・切断面・鏡映・市松・微小点）の再発なし
- 回帰: `tests/tiling.test.ts`（継ぎ目指標）、`tests/determinism.test.ts`（スナップショット更新済）

### 観察: 小キャンバスでのブロブ境界切断（tiling 固有ではない）

384×320 seed 777 で継ぎ目指標 4.4 が出た。原因を追うと、パッチ 4 のブロブ輪郭（半径 138 の円弧）が偶然 x=384 の継ぎ目に乗っていた。円弧は 34 行で 1px しかずれず直線に見える。これはトーラス処理の不備ではなく、クイルト方式が元から持つ「ブロブ境界で新シェイプの成長が止まる → 輪郭が円弧で切れる」性質が、小キャンバス（パッチ 5 個、境界リング誤差 0.4〜0.5 で 0.30 の閾値に届かない）で目立ったもの。512 以上では発生していない。

対策候補（未実施、必要なら Issue 化）: ブロブ半径外でも `nv === v`（同一シェイプの続き）の間だけ 1.25R まで成長を許す「シェイプ完走」。出力の最小サイズを 512 に制限する方が単純。

### 性能

トーラス化による生成時間の増加はほぼ無し（woodland 512: 約 0.8s、1024: 約 3.5s。フェーズ1 と同等）。`pasteBlobTorus` の共有訪問バッファは w×h バイト 1 本。

## v16: 高解像度時の多数決フィルタ（フェーズ4、2026-09-03）

### 問題

woodland 4096×4096 の生成が 10 分以上かかっていた（AOR2 は 41 秒）。原因は有機系の拡大時平滑化 `modeFilter` の半径:
`round(0.8/k × (w/512))`。`k = kBase × (512/w) × scale` に既に `512/w` が入っているため二重スケールになり、
4096px で半径 54（近傍 約 9,000 px × 1,670 万 px）、8192px では半径 216 になっていた。

### 対策

1. **半径式を `round(1.2/k)`** に変更。nearest サンプリングの階段幅は `1/k` px なので半径はそれに比例させる。
   1024px で 3（旧値と同じ）、2048 で 5、4096 で 10、8192 で 20
2. **`modeFilter` を行スライディング実装に**（O(r²)/px → O(r)/px）。円形カーネルの各行の半幅を前計算し、x を 1 進めるごとに各行で左端 1 px を減らし右端 1 px を足す。結果は素朴実装と完全に同一（縮小側の半径 1 も含めて全スナップショット一致）

### 結果

- woodland 4096²: 10 分超 → **約 46 秒**（AOR2 と同程度。残りはパッチ候補スコアリング・貼付の O(px) 部分）
- 目視: `tools/render.mjs --crop=512` で 2048 / 4096 の中央を等倍確認。半径 7（`0.8/k`）では 8px 階段が残ったため 1.2 に決定
- 256px スナップショット・タイリング指標 いずれも不変
- 512px でも scale < 0.95 の出力は変わる（例: scale 0.7 は k=0.665 で半径 1 → 2）。woodland 512px × scale 0.7 / 0.5 × seed 1234 / 777 / 211025 を目視: 微小欠片の消え過ぎ・輪郭の丸まり過ぎなし。scale 0.5 の斜め直線はブロブ境界の既知挙動（v15 参照）で本変更とは無関係

### 残課題

4096² で約 45 秒、8192² は数分。クイルトのパッチ候補スコアリングと貼付は px 数に比例するため、根本改善には
低解像度で形状を決めて拡大する（index マップの多段解像度化）か WebGL 化が必要。Issue #3 に追記。

## v17: 多段解像度生成と進捗コールバック（フェーズ4、2026-09-03）

### 多段解像度

クイルト系のパッチ候補スコアリング・貼付は出力 px 数に比例するため、v16 後も 4096² で約 46 秒、8192² は数分かかっていた。
ソース図案は 800×685 px なので、出力が大きくても形状の情報量は増えない（どの解像度でも同じソース px を nearest 参照する）。
そこで長辺が `baseMax`（既定 1024）を超える出力は、

1. 長辺 1024 に縮小したキャンバスで形状を決める（`k` は `512/w` を含むので自動的に整合する）
2. index マップを nearest で実寸に拡大
3. 平滑化（半径は実寸の `1.2/kFull`）と欠片除去だけ実寸で行う

| 出力 | v16 | v17 |
|------|-----|-----|
| woodland 2048² | 11.8s | 4.2s |
| woodland 4096² | 46s | 9.3s |
| AOR2 4096² | 41s | 4.4s |
| woodland 8192² | 数分 | 45s |

- 1024 以下は従来と完全同一（テストで確認）。256 スナップショット・512 タイリング指標 不変
- 目視: 4096² の等倍クロップで輪郭の滑らかさは v16 と同等、階段なし
- 継ぎ目: 2048² / 2362×1181 / 3000×2000 で確認。**注意**: nearest 拡大後は内部の隣接変化率が 1/f に落ちるため、
  継ぎ目指標（継ぎ目変化率 ÷ 内部変化率）は f 倍に膨れて見える。多段化した出力の継ぎ目は基準解像度で評価すること
- 残りの時間は拡大 + 多数決フィルタ + 欠片除去（いずれも O(px)）。8192² でさらに縮めるなら欠片除去の連結成分探索を最適化する

### 進捗コールバック

`generate(..., { progress })` で 0..1 を通知（クイルト: パッチ毎 → 0.75、穴埋め 0.8、平滑化 0.92、完了 1。成長: レイヤー毎）。
Worker が 2% 刻みでメインスレッドへ中継し、UI は

- プレビュー: まず長辺 192px の粗い結果を即描画（数十 ms）→ 本プレビュー生成中は左下バッジに進捗 %
- 書き出し: オーバーレイに進捗バー

を表示する。フリーズしたように見える時間を無くすのが目的。
