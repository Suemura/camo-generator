# 技術検証の記録（索引）

生成手法の変遷と自己改善ループの全履歴。**1 エントリ = 1 ファイル**で `docs/tech-verification/` に置き、
このファイルは索引だけを持つ。

## なぜ分割したか

以前は 1 本の長いファイルの末尾に `## vNN` を追記していた。迷彩プリセットを並行して追加すると

- **同じ末尾行を全員が取り合う**（3 本並行で 75 行の切り貼りが発生した）
- **連番そのものが衝突する**（Issue #24 / #25 / #28 が全員 v20 を名乗った）

の 2 つが毎回起きた。ファイルを分ければ前者が消え、番号をやめれば後者が消える。

## 新しいエントリの追加手順

1. `docs/tech-verification/YYYY-MM-DD-issue-NN-<slug>.md` を**新規作成**する（既存ファイルは触らない）。
   日付は作業日、`NN` は Issue 番号。**新しい番号（vNN）は振らない** — ファイル名が識別子
2. 下の一覧に 1 行足す。この索引は `.gitattributes` で `merge=union` にしてあるので、
   別エントリどうしの追加なら自動マージされる（順序が乱れたら日付順に直す）

既存の `v1`〜`v25` という番号は、本文中の相互参照（「v18 の残課題」等）が生きているため見出しに残している。
新規エントリからそれらを参照するときも `v18` のように番号で書いてよい。

## 読み方

生成品質に触れる変更を入れる前に、**該当手法のエントリを必ず読むこと**。過去に解消済みの
アーティファクト（ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点・平行な細線）と
その対策が全部ここにある。同じ轍を踏まないための記録なので、検証したら必ず追記する
（手順は CLAUDE.md「検証ワークフロー」と `docs/04-add-preset.md`）。
