# 生成手法の判断カタログ

生成コアを触る前に読む資料。ソース（`src/core/camo.js` のコメント）・テスト・PR・Issue から復元できないものだけを置く。

- 書くもの: 実物の特徴と手法の対応、症状 → 原因 → 対策、試して捨てた案とその理由、参照画像の測り方で踏んだ罠、指標の読み違え
- 書かないもの: 作業報告（「検証した」「不変を確認した」）、日付・Issue / PR 番号、点数・生成時間、残課題（Issue に置く）、パラメータの値と根拠（`PRESETS` のコメントに置く）
- 追記の単位は「新しい知見 1 つ = 該当する節に箇条書き 1 つ」。時系列の節は作らない。既に同じ知見があれば書き直す

## 手法の選び方

実物の特徴が手法を決める。パラメータで別の手法の見え方には寄せられない。

### クイルト `genQuilt`（実物図案のパッチ合成）

- 向く: 局所形状が手描きの設計言語そのもので、ノイズや解析形状では出ない図案（M81 系のブロブと黒枝、DPM の筆跡、タイガーストライプの爪状フリンジ、刷毛の掠れ）。ノイズ閾値系（`genWoodland` / `genDigital`、退役）はどう調整しても「同じ設計言語」にならなかった
- 前提: ソース図案が 1 リピート以上の範囲を持つこと。参照が図案の一部（袖の接写など）だと長距離のリズムを読めず、`topLayer` も破綻する（後述）
- 形状はソース図案で決まる。ブロブの丸み・輪郭の入り組み・斑点の有無はパラメータでは変えられない。似た色構成でも設計言語が違えば専用ソースを作る（DCU に M81 ソースの色統合は不可。陸自 2 型の斑点はドット層を足すのではなくソース図案に含める）
- 派生図案は形状を共有して `colors` / `remap` で作る。CCE は M81 ソースを `srcAspect` で横伸長、DDPM は DPM ソースを 4 値で合成してから `remap` で 2 値に統合する。実物の成り立ち（同じ版の色替え）と同じ手順になり、面積比も自動で合う
- **2 値のソースは使えない**。同色どうしの継ぎ目にコストが無いため、パッチ輪郭が大面積の内部を自由に通り、矩形・直線の切断面がそのまま境界になる。`kBase` / `patchR` をどう振っても消えない。2 色の図案は 4 値で合成して `remap` するか、別手法にする
- `topLayer`（最上層の版として刷り直す）の採否は、ソース画像の縁に接しない連結成分の合計面積 ÷ 目標面積で決める。縁で切れた成分は直線の断面が出るため使えないので、参照が 1 リピートより狭いと使える成分が枯渇し、同じ成分が鏡映を含めて何度も反復する。成分数ではなく面積比で判断し、比率はソースマップを直接ラベリングして数える。比率が十分でも「成分を丸ごと別の場所に置く」意味を持たない版（グリーン面の内部を櫛状に走る細線など）には使わない
- `kBase` は「ソースもパッチ半径も同じ比で縮める」ズーム操作。図案とパッチの大小関係を変えるのは `patchR`。パッチがソース上のブロブより小さいと継ぎ目がブロブ内部を横切り、内容の合わない箇所がパッチ輪郭の形（直線・三角）で出る。1 未満（拡大参照）は最近傍サンプリングで輪郭が階段化するので下限は 1
- 色比フィードバック（`deficit` → `divw`）はパッチ 1 枚ごとに働く。512px で 10 枚を割ると `divw` を振っても出力が 1 bit も変わらない。線図案はパッチを大きく取りたくなるが、面積比を合わせたいなら枚数が優先
- 候補スコアが境界リング誤差に支配される図案（DCU など単純なブロブ）では `frac` / `divw` は効かない。色比は `kBase` / `patchR` で調整する
- 細線を持つ図案（縞・刷毛目・飛沫）には `fineDetail: true` を付ける。付けないと後処理が細部を消す。ブロブ図案に付けると継ぎ目のカスが線状の点々として散る（後述）
- 縞図案には `slopeLock: true`。既定では x 反転と y 反転を独立に振るため約半分のパッチで縞の傾きが逆転し、隣接パッチで縞が「く」の字に折れる
- 全面をパッチで被覆する設計なので、地色比は `patchR` では動かない（ソースの面積比と色比フィードバックで決まる）

### クラスタ成長 `genGrowth`（セル格子上の面積予算つき成長）

- 向く: 正方セル格子のピクセル迷彩（MARPAT / CADPAT / UCP / EMR / NWU / 07 式）。輪郭が元から直交階段の図案（ベリョースカのステンシル版）にも向く。格子の階段はこのエンジンの構造から出るので、後処理で足すより実物の成り立ちに近い
- 本体は変えずに `layers` のパラメータだけで派生を作る。`elongX` / `elongY` で異方性、`eat` / `seedNear` で層の依存関係（「黒は緑の内側に落ちる」「タンは白の縁に重なる」）、`stratify` で分布の均一化を表現できる
- 地色が明色でない図案（NWU のネイビー地、07 式海洋のブルー地）は index 0 に地色を置く。`colors` の並びが明度順にならないのは意図
- `ratio` は「その層が塗る予算」で、後続の層に食われるため最終面積と一致しない。参照の面積比を目標に置き、生成結果の index 分布から逆算する
- `stratify` のスロット数はクラスタ数に合わせる。スロットをシャッフルして先頭から消費する実装なので、スロット数がクラスタ数より大きすぎると「36 個中 13 個をランダムに選ぶ」ことになりかえって偏る。逆にクラスタ数が層化スロット数を大きく超えると残りがランダム配置になり帯状の空白が出る
- `compact` を下げると前線が固まらず葉柄状に伸びるが、下げすぎると motif が繋がって画面を横断する紐（DLA 状の枝）になる。「細さ」と「独立性」は独立に制御できない
- `cellPx` は scale に依存しないので、scale を下げると motif が大きく数が減る。極端な scale では 1 セル単位のノイズに近づく
- 面積予算方式は「多数の小クラスタ」に弱い。`growLayer` の反復上限に当たって予算を使い切れなくなるため、粒度に下限がある
- 同族の図案でも層構造が違えば `layers` を書き直す。07 式海洋型は林地型の色替えではなく、白と緑が独立して地に散る別の連鎖だった。色替えで済むかは参照の隣接関係（各版がどの版に接するか）を集計して判断する

### 斑点配置 `genSpots`（地色に版ごとの解析形状を刷り重ねる）

- 向く: 独立した丸い斑が地色の上に散る、または同じ版の斑が融合して「円弧の連なり」の塊を作る図案（フロッグスキン、フレックターン系）。枝分かれ・切り合いがある図案（M81）、直交階段（ベリョースカ）、直線（スプリンター）には向かない
- 輪郭は極座標の 5 次までの高調波。高調波を増やすと M81 の枝分かれや陸自 2 型の斑点分岐に近づき、「輪郭の単純さ」という識別点が失われる。分岐する形はこの手法では作れない
- 実物図案を使わない手続き生成なので、参照画像のライセンスが派生物に及ぶ（CC BY-SA）迷彩でも実装できる。参照は目視比較とパレット実測にのみ使う
- `gap` を負にすると同じ版の斑が接触・融合する。塊を大きな斑 1 個で作ると単純な楕円になり別物に見える
- `halo` は「その斑を刷る直前に同じ輪郭をひと回り大きく別の版で刷る」。重ね刷りで下の版が縁として残る構造（ブラウン斑をグリーンが縁取る）をそのまま表現する
- `clump` は斑の中心座標を低周波ノイズで間引く。境界に掛かった斑は丸ごと刷られるので境界が直線的にならない。塊の寸法は斑と同じ「512px・scale 1.0 基準 px」で持つ（後述の轍）
- 同一図案の配色替えは層定義を 1 か所に置いて参照で共有し、`colors`（色数が減るなら `remap`）だけ差し替える。共有元を変えると全変種の出力が変わる。変種ごとに面積比を合わせ込むことはできず、「同一図案である」事実と引き換えに受け入れる
- 各層の配置が独立なので、層間の相関（「暗色の斑が別の版の斑に接して対になる」「斑が縦に連なる」）は `halo` 以外では再現できていない
- `dots` は層スタンプ後の index マップを六方格子でサンプリングし、格子点ごとに円板を**層の刷り順優先**で描き直す後処理。点描様式（M05）の「輪郭が円弧の連なりに階段化し、孤立した 1〜3 ドットの小片が散る」識別点はこれで出る。ピクセル系の直交階段（`genGrowth`）とは別物なので `genGrowth` では作れない。円板半径は六角セルの外接半径（0.577 ピッチ）以上にして内部を塗り潰す。優先順を色 index 値ではなく `layers` の順で持つのは、remap 併用や層順 ≠ index のプリセットでも「後刷りが前刷りへ膨らむ」が壊れないため。低優先の孤立ドットは周囲の高優先円板に削られて 10〜15px² の欠片になるので `minFrag` はその上・1 ドット（≈ 55px²）の下に置く
- 点描様式の 2 色版（M05 雪型）を多色版の `remap` で作る案は面積比と偏在が合わない（`[0,0,0,1]` で暗色 0.30 / 塊り比 62、`[0,0,1,1]` で 0.56。参照は 0.364 / 47）。同一図案の色替えでない（版が 1 つの別図案）ので、`dots` と `r` 分布だけ共有した別 `layers` にする

### 幾何ハードエッジ `genSplinter`（パワー図による平面分割）

- 向く: 輪郭が全て直線で、三重点が多い（重ね刷りの「乗せ」ではなく平面の「分割」）図案。クイルトはパッチの継ぎ目で多角形が切られて偽の頂点が並び、成長系は階段が出るので不可
- 素のボロノイは平均 120° の鈍角セルに寄る。重み付き（ラゲール距離）にすると二等分線は直線のまま重みの小さいサイトが細長い楔になり鋭角が出る。サイトごとに違う計量を持つ異方ボロノイは二等分線が曲線になるので不可（全体で 1 つの線形変換なら直線が保たれる）
- 色割当の統合項は確率ノブにする。「不足率 + 統合項」を足して最大を採る形にすると、色が均衡した後の不足率の差が 0.01 未満しかなく統合項が必ず勝ち、1 色が画面の半分を覆う
- 雨線は欠片除去より後に描く。先に描くと 1px 幅の線が欠片として併合される
- 多角形の鋭さには構造的な上限がある。パワー図のセルは正六角形に寄るため、実物のスプリンターの「鋭い先端の密度」には届かない。同じ限界で M90 は成立しない
- ソース図案を持たず計算量が画素数に線形なので `baseMax` を参照せず常に実寸で生成する。縮小生成 → 最近傍拡大の経路を通らないため、ハードエッジが階段化しない

### 雨線 `genRain`（列レーン + 列位相の縦ダッシュ）

- 向く: 無地の地色に独立した短線だけが並ぶ図案（シュトリヒタルン系）。ブロブもセル分割もない
- 識別点は「縦の列に緩く揃う」「同じ列の上下は接触しない」「長さ・太さ・傾きにばらつき、端は丸い」。列ごとの定数 x オフセットと縦位相で格子由来の横帯を消し、長さを「セル高 − 最小隙間」以下に clamp して列内非重複を構造的に保証する。ダッシュ個別の x ジッタは小さく取る（大きいと隣列と融合する）
- 面積比はセル採用率 `density` と線形に対応するので、目標フィードバックは持たない
- `genSplinter` の雨線 `applyRain`（1px 固定幅・傾きなし）とは別関数。統合すると splinter の出力ハッシュが変わる

### 使わない手法

- **ノイズ閾値 + 等高線バンド**（`genWoodland` / `genDigital`）: 「破線 ⇔ リボン」の振動と「輪っか」をパラメータで完全には制御できず、実物の設計言語にならない。コードは退役プリセットとして残置
- **矩形グリッドの Image Quilting**: 直線シームが平坦色領域の不一致部で必ず露出する。ドメインワープでの隠蔽は櫛歯化・帯状化で失敗した。有機輪郭パッチ + 領域成長型シームに置き換えた
- **異方性ノイズの多値閾値化 `genStripe`**（縞・刷毛目向け）: 帯の輪郭が常に滑らかで、縁から枝が分岐する「爪」や毛先の割れ・飛沫が原理的に出ない。幅を 0 まで変調しても縞が細るだけ。縞・刷毛目はクイルトで作る
- **ポリゴン再帰分割**（camogen 方式）: 実物模倣では不採用。オリジナル迷彩生成の候補として `prototype/experimental/` に残置

## 既知アーティファクト（症状 → 原因 → 対策）

新しい症状はまずここと照合する。同じ症状でも原因が別のことがある（「1px の筋」は 3 種類あった）。原因は推測せず、後処理を 1 段ずつ外す ablation で特定する。

### クイルト系

- **ブロック感・直線シーム**: 矩形グリッド quilting の構造的問題。有機輪郭パッチに変更
- **鏡映対称（蝶々状）**: ソース参照の折返し（reflect）がパッチ内に入る。パッチ中心相対サンプリング + 折返し不要なソース範囲選択。`km` の裸参照が 1 箇所でも残ると（`srcAspect` 導入時に踏んだ）安全折返しが常用経路に入り即座に再発する。高スケールでベース層を敷いていたのも原因の 1 つで、ベース層は廃止して未塗布センチネル 255 から全面をパッチで被覆する
- **境界で色が急変する箇所**: 境界リング誤差の重みを上げ、誤差が閾値を超える中心は再抽選する。「貼っても境界線が出ない場所」を探してから貼る
- **シェイプが「バサッと」切断される**: リング誤差最小化では途中切断を防げない。領域成長型シーム（コアのみ無条件貼付、外側は「新値 = 旧値」「新シェイプ自身の連続」「未塗布」のみ拡張）で、色の遷移を必ずどちらかの実シェイプ輪郭上に乗せる
- **半円状・円弧状の切れ目、輪状の帯**: 領域成長がブロブ半径 `rad(θ)` で無条件に打ち切られ、半径をまたぐシェイプが「続きの無い滑らかな弧」で切られる。設計文書に「半径を超えて成長を許可」と書いてあってもコードに存在しなかった（文書と実装の乖離）。対策はシェイプ単位の二択: 同色の続きを自然な輪郭まで塗り足す「完走」か、そのシェイプを塗る前に戻す「撤回」。途中で止めない。選択は色の不足度（目標比を下回る色だけ完走）。撤回域にしか接しない新シェイプの島も戻す（残すと図柄だけが蓄積して黒比が上がる）。副作用として `tileable: false` の出力も変わった
- **直線の切断面（パッチ中心の対蹠点を通る）**: トーラス上でパッチが自分自身と重なり、同じ画素へ 2 方向から別内容の前線が到達する。パッチ半径の上限を `0.42·min(w,h)`（横伸長時は `min(w/sA, h)`）に制限。`patchR` を上げるとここに当たるので、切断面の頻度は `patchR` に対して単調でない
- **直線的・機械的な境目 + 市松状ノイズ（高スケール）**: 前者は上記の半径クリップ、後者は `k > 1.4` の最近傍縮小のエイリアス。多数決ミップマップ（2×2 多数決で段階縮小し、`k ∈ [0.7, 1.4]` になるレベルからサンプル）
- **高スケールで微小点が残る**: フラグメント除去閾値がスケール反比例で縮む。画面基準の絶対下限 `max(70, 110/scale²)` を置く
- **小さな孤立シェイプ（小石・チップ）が消える**: 多数決ミップ・領域成長シーム・欠片除去のすべてが数 px の孤立点を消す。ソース図案に含めず、後処理と多段解像度の拡大が終わった実寸 index に直接描く（`applyChips`）。この位置でしか 1〜2px の黒縁は成立しない
- **黒（最後に刷る版）が他色に切り抜かれて見える**: パッチ合成は全色を同時に持つので、後から貼るパッチの輪郭が既存の黒を削る。パラメータでは直せない。`topLayer` で黒を消して下刷りを作り、ソースの黒成分を丸ごと刷り直す
- **1px の筋（3 種）**: (1) `k ≈ 1` では多数決フィルタを掛けない設計なので、パッチ輪郭同士の交差でできる 1px の帯が残る → `cleanupSlivers`（左右または上下の隣が互いに同色で自分だけ違う画素を倒す）。(2) `topLayer` で黒を消した跡を最近傍 BFS で埋めると、幅 1〜3px の黒枝の内部が「回廊」になり、枝の端から入った遠くの色が 1〜2px の筋として奥まで伝播する。M81 の黒枝は平行に走るので筋も平行に複数本出る → 8 近傍の多数決で 1 層ずつ膨張させる（回廊の壁はその領域自身の色なので遠くの色が生き残れない）。(3) ソース図案そのものに皺の稜線・影が細帯として残っている（布地写真）→ `gen-src.mjs --thin`（幅で判定するオープニング。面積では落ちない）
- **同じ黒成分が画面に何度も反復する（鏡映含む）**: `topLayer` で使える成分が枯渇している。参照が 1 リピートに満たない。`topLayer` を外す（前述の面積比で判断）
- **黒が一箇所に固まり残りが素抜け**: `topLayer` の置き場所選びが下地一致だけだと良い場所に集中する。既存の黒との重なりと区画ごとの黒密度で減点する。目標面積の 3 割を超える大成分を捨てると、M81 の長い枝分かれ（bbox 充填率 0.25）が全部落ちて語彙が失われる。上限は 6 割にし、固まりの抑制は密度ペナルティと使用回数の平準化に任せる
- **ソース画像の縁にある矩形状の黒**: 縁に接する成分を `topLayer` で丸ごと刷った。縁で切れているのは図案ではなくスキャンの縁なので除外する
- **細線・掠れ・飛沫が消える（ストローク系）**: 主犯は `cleanupFragments`（設計内容の 5〜6% が 110px² 未満のサイズ帯にあり、その 95〜98% を削除していた）、共犯は `cleanupSlivers`。多数決ミップは `km < 1.4` で走っておらず無関係だった（当初の誤診）。「細い」だけでは微小点と区別できないが、「細く、かつある向きに長い」なら分離できる（`thinLineMask`、4 方位）。マスクは実寸拡大の**前**に作る（拡大後は階段の畝まで細長い構造と誤認する）。平滑化での保護は縮小サンプリング時のみ（拡大域では細部の幅も 1/k px あって消えないので保護しないほうが正しい。外したら 2048px の輪郭が総ギザになった）
- **ブロブ図案に「線状の点々」が散る**: 上記の細部保護をクイルト系全体に適用した副作用。ブロブ図案には守るべき細線が無い一方、パッチ継ぎ目の削れカス（幅 2〜3px・長さ 10〜30px）が「細くて長い」に一致する。区別しているのは「その図案に細線が設計として存在するか」という前提知識で、それはプリセット側の情報（`fineDetail`）。再現度スコアはブロブ図案でも上がって見えたが、スコアの上昇が品質の向上とは限らない例
- **細線が高スケールで潰れる（縞図案）**: `k` が上がるとソースが縮小参照され、多数決ミップが 1〜2px の細線を落とす。線図案固有の弱点で、対策は無い
- **高スケールで未塗布 255 が残り `toRGBA` が落ちる**: 未塗布埋めループの反復上限が固定だった。パッチが小さく穴の数が scale² で増えると埋め切れない。上限を画素数基準にする
- **横長図案で継ぎ目指標が誤検知**: 後述「計測と指標」

### 成長系・斑点系・幾何系

- **ツイッグの「輪っか」**: 等高線由来。ツイッグ判定を superCell 単位のブロック量子化にすると自然なブロック連なりに解消（成長系移行前の話。現行 `genGrowth` では出ない）
- **ネイビーの帯状の空白（層化シード不足）**: クラスタを小さくするとシード数が層化スロット数を超え、残りがランダム配置になる。`stratify` を上げる
- **単セルの点が大量に出る（高 scale）**: `min` / `max` が `/scale²` されるので、`min` が小さすぎると scale 2.0 で 1 セル台になる
- **斑点の塊がスケールに追従しない**: `clump` をキャンバス分割数で持っていた。斑の半径は `u = (w/512)/scale` でスケールするのに密度場はしないので、スケールを上げるほど塊が図案に対して巨大化する。目視では気づけず、`analyze-spots.mjs` の塊り比で発覚。塊の差し渡しを 512px 基準 px で持ち、`u` で分割数を求める
- **ある版が画面中央に 1 個の島として出る**: `clump` を排他ゲートにした。参照 1 枚の一場面から「この版は塊としてだけ現れる」と誤読していた（後述「参照画像」）
- **砂粒状のノイズになる**: 指標に合わせて斑を縮めすぎた（後述「計測と指標」）
- **斑の輪郭に多角形の折れ（高解像度）**: 角度 LUT の分割数が固定だった。周長に比例させて 1 ステップが 1px 未満になるようにする
- **欠片除去で 1px が取り残される**: `cleanupFragments` は 1 走査で併合先を決めるため、「A を B の色へ併合 → 直後に B が別の色へ併合」の順で A の画素が残る。3 個以上が数珠つなぎになる稀なケースもあるので、変化がなくなるまで繰り返す不動点ループにする
- **ペッパー状の微小片（幾何系）**: 楔セル由来。`minFrag` を参照の粒度に合わせる
- **雨線が塗り潰しになる（高 scale / 小キャンバス）**: 線の太さは 1px より細くできないため、`u` が小さいと間隔だけが縮む。列間隔の下限を太さの倍数で切る
- **ジッタ格子の周期リズム**: `jitter > 1` でサイトが自分の格子セルを出るようにすると格子の痕跡が残らない

### 意図した階段とアーティファクトの階段

階段化は基本的に除去対象だが、ベリョースカの直交階段は実物の版そのもの。混同しない。

- アーティファクト: クイルトでソースを拡大参照（`kBase < 1`）したとき、最近傍サンプリングが本来滑らかな輪郭を段差にする。ステップ幅が不均一で解像度を上げると消える
- 特徴: `genGrowth` のセル格子が元から階段である輪郭を再現している。ステップ幅が `cellPx` 一定で揃い、解像度を上げても保たれる。境界に孤立ピクセルが無い（`growDither: 0`）ことが MARPAT 系との識別点
- 判定は等倍クロップ（`--size=2048x2048 --crop=512`）で行う

## 試して捨てた案

同じ轍を踏まないための記録。手法別。

### クイルト

- 半径の外に「完走帯」を設けて半径比 1.45〜1.9 まで同色の続きを伸ばす: 切れ目が外側の弧に移るだけ。ノイズで外縁を揺らすと旧色の帯（C 字・輪）が残る。「どこで止めても、その形の切れ目や帯が残る」のが本質で、シェイプ単位の完走 / 撤回に至った
- 内側輪郭を高周波ローブ化: 隣接パッチの輪郭が小半径で交差し、細い C 字帯が増えた
- 完走に「同色域の通過」を許す: 面積の大きい色だけが遠くまで伸び、小面積色が痩せる
- 候補スコアリングやソース参照範囲に成長箱 `bb`（内側半径の箱 `bbIn` ではなく）を渡す: ソース中央に固定され全パッチが同じ図案になる
- 横伸長を面積保存の √分割（`kmX = km/√a, kmY = km·√a`）で作る: 縦が縮んで「M81 を横に伸ばした」ではなく「M81 より細かい別図案」に見える。y を等方時と同一レートに保つ純 x 伸長にする。`kmX < km` は縮小方向ではないのでエイリアス源にならない
- 横伸長でパッチ輪郭を円のまま残す: 図案の特徴だけが伸びて「特徴 / パッチ」の比が x 方向だけ崩れ、単色パッチが増える。単色パッチの輪郭はブロブ半径そのものなので滑らかな弧が境界として露出する。パッチも同じ比の楕円にする
- 横伸長でパッチ枚数を面積被覆基準にする: 枚数が 1/sA に減り、色比フィードバックの反復不足でシード間の面積比の振れが大きくなる。枚数を等方時と揃える
- 横伸長で `divw` を上げて緑比を回復する: 1 パッチが参照するソース領域が横に狭まり、緑優位の候補自体が存在しないので重み付けでは解けない
- 2 値のソース図案（DDPM を独立スキャンから作る）: 矩形の切断面。前述
- DPM ソースを共有して「黒 + 緑をブラウンへ統合」: 面積比が砂 0.17 : 茶 0.83 になりサンド地にならない（DPM は緑が地）。実物の版の統合（明 2 色 → サンド、暗 2 色 → ブラウン）に合わせる
- 縞図案での `topLayer: 0`（面積比は回復する）: 刷り直された成分が細線ではなく淡い塊として浮く。面積比より見え方を優先して不採用
- 縞図案での `srcAspect`: 図案が粗くなり直線的な切断面が出た
- 細部保護をクイルト系全体に適用: 前述の「線状の点々」

### 成長系

- 既存 PD ソース図案の流用 + `organic: false` + `remap` でステンシル図案を作る: (i) 丸いブロブから分岐形はパラメータでは作れない、(ii) 2 値クイルトの矩形切断面が「意図した階段」と見分けられなくなる。最悪の組み合わせ
- 新しい `kind`（葉状シルエットの手続き生成 + セル量子化）: 量子化・トーラス・進捗・面積予算の再実装で `genGrowth` の完全な重複
- 縦異方性のために成長方向バイアスを新設する: `elongY` が既にあった。本体を触らず `layers` で書く

### 斑点系

- 塊の寸法をキャンバス分割数で持つ: スケール非追従。前述
- 参照 1 枚の一場面から版の偏在を決めて排他ゲートにする: 前述
- 等価半径の中央値を参照に合わせて斑を縮める: 参照が JPEG だとアンチエイリアスの微小成分が中央値を下げる。前述「計測と指標」
- 配色替えの版対応を明度順で決める: 明度順は保存されていない（Arid の最暗版が M/84 の最明版に対応する）。同寸に揃えて量子化し、画素単位で交差集計する。リサイズは最近傍でないと版と版の中間色が偽クラスタを作る（双線形で一致率が 60% 台に崩れる）
- 受理判定に `rng()` を使う: `clump` を持たない既存プリセットの rng 消費列が変わって出力が壊れる。`hash2` で判定する

### 幾何系・雨線

- 異方ボロノイ、加算式の統合項: 前述
- 単独レンダの掃引で最終パラメータを決める: 単独では「らしく」見えるが `--compare` で並べると 2 倍粗かった。掃引は倍率の当たりを付けるまでにし、最終値は必ず `--compare` で決める
- 雨線を `applyRain` の拡張で作る: splinter の出力ハッシュが変わる。別関数にする

## 参照画像とパレット実測

`tools/gen-src.mjs` / `tools/extract-palette.mjs` のオプションの選び方は `docs/04-add-preset.md` §4 が手順。ここはその手順に至った理由と罠。

- **フラットなスウォッチを最優先で探す**。布地写真は最後の手段。ドレープした布地では分散の第一主軸が明度になり（インク間の RGB 距離 20 に対し明暗の距離 80）、RGB 空間の k-means は必ず明度方向に切る。`--flatten` は照明成分の推定に図案が混ざって色相差ごと平坦化してしまう
- **布地写真の 3 つの破綻とオプション**: 織り目の斜め筋が色の分散として効き k-means が明度で切る → `--blur`。周辺減光が最も暗い値へ丸ごと量子化され黒の面積比が倍に膨らむ → `--flatten`。輪郭のアンチエイリアスがパレット重心を隣接色へ引く → `--core`
- **`--flatten` の sigma は図案のブロブ幅より十分大きく取る**。実体は「強くぼかした自分自身で割る」フラットフィールド補正なので、sigma がブロブ幅と同程度だと図案そのものが照明成分として推定され、大面積色の内部が補正されて潰れる。ブロブ幅 50px の図案で効いた値を幅 200px の図案に使うと砂色の面積比が 3% に潰れた。襞のスケールがブロブ幅と同程度の制服写真では使えない
- **前処理の窓が狭いことがある**（皺のある着用写真）。`--flatten` が強いと皺の陰影で地色が明部 / 暗部に割れて 5 色目が失われ、弱いと別の色が割れる。部分切り出しは、統計を取るのに全面が要る色（画面全体に散る小斑）を失う
- **k を色数より多く取る**のが要る場合: 織り目と陰影が 1 つの版を 2〜3 クラスタに割る（k=5 でブラウンが 3 分裂）。役割ごとに内部画素数が最大のクラスタを採る。輪郭のアンチエイリアス（版と版の混色）が 1 クラスタを占有して小面積色が落ちる場合も同じ。制服写真の影は k を上げて独立クラスタにし、隣接色の集計（白・タンに接しない = 版ではなく襞）で判別して捨てる
- **JPEG のリンギング**: 細い筆致としてしか出ない色は、白 ⇄ 緑の中間灰が「茶」クラスタに大量に吸われて重心が灰へ流れる（内部画素が数百個 = 実体のないクラスタ）。k を上げても中心は灰軸に乗る。筆致内部（近傍がすべて暖色）の中央値を採る
- **k-means が使えないときは色相ゲート**: 制服写真で 4 版 + 影 + 装具が混ざると、小面積の版が「地色の影」クラスタに吸収される。版ごとに色相・彩度・明度の条件で画素を集めて中央値を取り、写真ごとに比較する。露出で中央値は大きく動く（青が #456b86〜#87b4da）ので、飽和していない写真を選ぶ
- **`--max-edge` は細線図案では原寸に**。既定の縮小は UI の抽出と揃えるための値で、ブロブ図案では問題ないが、数 px 幅の細線が版の 1 つになっている図案では細線が混色して消え全色が中間色側へ寄る
- **ソース図案と同じ量子化重心をパレットにする**選択肢がある。照明ムラで `extract-palette.mjs` の砂色が明部 / 暗部に割れるとき、`gen-src.mjs` が stderr に出す重心を採れば形状と色が同じクラスタリングに基づく
- **文献と実測が食い違ったら実測を優先**する。フロッグスキンのビーチ面は文献では 3 色だが入手したスウォッチは 4 色。M1942 は製造元・時期で配色に幅がある
- **参照写真の色被りは補正しない**。青寄りの写真からダークグリーンが青緑として測れても実測値のまま採用し、中立な参照が入手できたら測り直す
- **Issue 本文の色・層構造は参照と食い違うことがある**。「濃紺」は襞の影、「淡い地に緑の塊」は実物の色反転だった。実装は参照の実測に合わせる
- **1 枚の写真から分布を読まない**。布地写真は大きなリピートの一部しか写っておらず、ある版が固まって写る一場面から「その版は塊としてだけ現れる」と読むと逆になる（実際は 3 版中もっとも一様に散る版だった）。全体が見えるスウォッチで塊り比を測る
- **参照の縮尺は比較ツールの表示と同じ係数で換算する**。`render.mjs --compare` は参照を cover で縮小するので、4:3 の写真を正方形に並べると高さ基準の 0.667 倍になる。0.5 倍で組むと統計は「一致」なのに `--compare` で一段細かく見える
- **同一図案の色替えスウォッチは形状の根拠にならず、配色替えの根拠になる**。Wikimedia の各国フレックターン変種（同一ベクター図案の色替え）は形状の実測には使えないが、図案が同一と確定しているので形状を共有して色だけ差し替える根拠にはなる
- **参照が 1 リピートに満たない**（袖の接写）と、長距離のリズムを読めないまま形状パラメータを決めることになる。クイルトのソースにも `topLayer` にも使えない
- **セル寸法は量子化後の水平ラン長の平均で測る**。設計グリッドに位相が揃っていないので剰余ヒストグラムでは検出できない
- **絶対スケール（512px が実寸何 cm か）は制服写真からは取れない**。同ファミリーで粒度が同じという前提か、ポケット幅などからの概算に留まる
- **面積比のターゲットは図案の要素だけで取る**。皺・影を含む「暗色比」ではなく、ダッシュ判定成分の面積比を使う。皺で切れた短い成分（長さの下位 25%）は寸法の統計から外す

## 計測と指標

数値は目視の代わりにならず、目視は数値の代わりにならない。両方要る。

- **継ぎ目指標**（`tests/tiling.test.ts`）はラップ行（列）の色変化数 ÷ 内部行（列）の p90。平均を分母にすると、横縞状の図案では行あたりの変化数に重い尾があり（黒枝の帯を横切る行は中央値の 5 倍以上）、健全なラップ行が過大評価される。y ラップは縦隣接で正規化する（横方向で正規化すると横長図案で分母が縮む）。多段解像度で最近傍拡大した出力は内部の隣接変化率が 1/f に落ちるので指標が f 倍に膨れる。基準解像度で評価する。成長系はセル格子単位で測る。1 列の指標は分散が大きいので複数シードで判定する
- **塊り比・等価半径**（`tools/analyze-spots.mjs`）は `kind: 'spots'` で必須。目視では `clump` の効きすぎとスケール追従漏れを検出できない。等価半径 r50 は参照が JPEG だと輪郭のアンチエイリアスが微小成分を大量に生んで中央値を下げるので、**絶対値ではなく地色を 1 とした版どうしの比**で見る。絶対値に合わせて斑を縮めると砂粒状のノイズになる
- **縦ダッシュの幾何**（`tools/analyze-rain.mjs`）は `kind: 'rain'` で推奨。列位相・列内非重複・統計的ばらつきは単独レンダの目視では判別できない
- **再現度スコア**（細部保護の判定に使った thin1 / thin2 / small / perim / compN / frac の加重）は、基準を「ソース図案を面積多数決で canvas スケールへ落としたもの」にする（最近傍間引きは階段ノイズで周長を過大評価する）。実物より細部が多い場合も減点する（上振れを許すと後処理の無効化に最適化される）。**ブロブ図案では実物側の細部とパッチ継ぎ目のカスを区別できないので使えない**。布地写真をソースにしたプリセットでは実物側に織り目・皺のノイズが混ざるので `--blur` を掛けた基準で測る
- **面積比の読み方**: クイルト系はシード間の振れが ±5pt 前後ある（パッチ 11 枚では 1 枚の当たり外れが 1/11 の重み）。低 scale では巨大パッチが 4〜5 枚しか置かれず 1 枚の色偏りがそのまま面積比になる。成長系は予算方式なので振れがほぼ無い。`divw` を変えて出力が 1 bit も動かないなら、色比フィードバックが働いていない（パッチ枚数不足か、境界リング誤差の支配）
- **ソースマップの成分ラベリング**は `gen-src.mjs` の出力ではなくマップを直接数える（`topLayer` の可否判定）
- **縞状領域の検出器**（±6px の範囲に色変化が 4 回以上ある画素のクラスタ）は、高スケールで模様が細かい領域を拾うノイズがある。該当箇所を等倍で拡大して筋の実在を確認する
- **面積比が「一致」しても見え方は別**。統計を合わせたあと `--compare` で並べて初めて縮尺の誤りに気づいた例が複数ある
- **ドット格子のピッチと格子型は境界画素の自己相関で測る**。塊のマスクをそのまま自己相関すると大きな塊の相関に埋もれて格子の周期が出ない。マスクの 4 近傍境界画素だけを残して自己相関すると、格子ベクトル（M05: (0,8)・(±7,±4)・2 次 (14,0) = 正三角格子ピッチ 8px）が局所極大として出る。参照 2 枚で格子の向きが 90° 違っても、向きは識別特徴でないので生成では固定する

## 決定性と互換

生成経路の変更で既存プリセットの出力を壊さないための注意。

- **rng の消費順**: `mulberry32` のストリームは呼び出し順で決まる。新しい knob が rng を消費すると、その knob を持たないプリセットの出力まで変わる。既定値の経路では消費列を変えない（`slopeLock` は true のときだけ `rng2()` を消費しない側に寄せ、`clump` は `hash2` で判定する）
- **既定値で恒等になる実装**にする。`srcAspect` 既定 1 で `km / 1` はビット単位で同一、`stampSpot` の `grow` 既定 0 で `g = 1` の乗算、`remap` 無しは素通り。knob だけを先に入れて全スナップショット無変更を確認してからプリセットを追加する
- **色数の一般化**は既存の 4 色固定箇所（`cnt4` / `hist` / 未塗布判定 `< 4` / `modeFilter` の色数 / `cleanupFragments` の `cnt`）を全部通す。`Int32Array(nColors)` の `counts[4]++` は黙って捨てられ、平滑化で 5 色目が全消えする。RLE は k > 4 で値 3bit + ラン 5bit、`decodeSrc` の `bits` 既定 2 で既存ソースは再生成不要
- **共通後処理の変更は全プリセットに波及する**。`cleanupSlivers` や下刷りの膨張はクイルト系全部のハッシュを変える。並列 Issue の統合後に自分のプリセットのハッシュだけが変わることもあり、その場合は `--compare` / `--tile` で劣化がないことを目視してから更新する
- **`merge=union` したスナップショット**は行の並びがキー順と食い違ってテストが落ちる。ハッシュ値ではなく順序だけの不一致か確かめてから `pnpm test -u`
- **プロトタイプは `camo.js` のスナップショット**。再ビルドを忘れると古い実装が焼き付いたまま残る（`tests/prototype-sync.test.ts` が検出）
- **座標丸めは `Math.floor`**。`|0` は負側で 0 方向に切り捨てるため x=0 の列が 2 重サンプルになり、トーラス上で成長前線が止まる。訪問管理はパッチローカルではなくキャンバス座標で行う（パッチがトーラス上で自分自身と重なるため）
- **決定性を保つ配置**: ポアソンディスクの棄却サンプリングは走査順に依存する。ジッタードグリッド + 座標ハッシュ、または候補固定数のベストキャンディデート法にする。多数決膨張は結果をスイープ後にまとめて反映する（走査順非依存）
- **格子はキャンバスを厳密に割り切る**（`cw = w / round(w / target)`）。トーラス上で格子が閉じ、タイル境界に継ぎ目も格子ずれも出ない。周期ノイズは格子 index を `wrapI` で畳む（非周期の `vnoise` / `fbm` を `tileable` 生成に使うと継ぎ目に低周波の段差が出る）
- **`baseMax`（多段解像度）を参照するのはクイルト系だけ**。ソース図案を持たず計算量が画素数に線形な手法は常に実寸で生成し、`baseMax` 指定時とのビット一致をテストで固定する
- **多段解像度の半径式**は `1/k` に比例させる。`k` に既に `512/w` が入っているので、さらに `w/512` を掛けると二重スケールになり 4096px で半径 54 になった
- **多数決フィルタは行スライディング**（O(r)/px）。素朴実装と結果は完全に同一
