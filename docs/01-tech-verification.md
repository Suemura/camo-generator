# フェーズ1: 技術検証メモ

## プロトタイプ

`prototype/index.html` — 依存ライブラリなしの単一 HTML。ブラウザで直接開けるほか、Artifact として公開済み。

## 生成アプローチ

すべて **シード付きハッシュベースの値ノイズ（value noise）+ fBm（多オクターブ合成）+ ドメインワープ** で構成。乱数は `Math.random` を使わず座標ハッシュで決定的に生成するため、同一シード → 同一結果が保証される。

### 形状と色の分離

形状はスカラー場（Float32Array）として生成し、分位点（quantile）で閾値を決めて色スロットに割り当てる。この構造により:

- 色の面積比がパレットに依存せず一定に保たれる
- パレット差し替えは再着色のみで即時反映できる

### パターン別の手法

- **ウッドランド (M81)**: 横長異方性（X周波数 < Y周波数）+ 強ドメインワープの fBm を3層重ね。黒層はスカラー場の「等高線バンド」（分位点0.46〜0.55の帯）で枝状の細長い形状を再現
- **マルチカム / OCP**: 低周波場をタン→ペールグリーン→オリーブの連続グラデーションにマップした地に、茶斑（コアはダークブラウン）+ 高周波の明色小斑・暗色小斑を重ねる
- **デジタル系 (MARPAT / AOR1 / AOR2 / UCP)**: セルグリッド上で低周波（大領域）+ 高周波(エッジのギザつき)を合成し、指定面積比の分位点で N 値量子化

## v2 での改善（フィードバック反映）

初期実装は精度不十分（全パターン同系ロジック・実物特徴の欠如）だったため、以下を実施:

1. **目視反復ループの構築** — `camo.js`（生成コア、browser/node 共用）+ `render.mjs`（Node で PNG 出力）で、生成結果を実物参照画像（Wikimedia の M81 / MARPAT / UCP 布地写真）と目視比較しながら調整。`node render.mjs <outdir> <seed>` で全プリセット出力
2. **ウッドランド黒層の作り直し** — 等幅の等高線バンド → 「可変太さの枝」。芯線フィールドからの距離を別ノイズで変調した太さと比較。テーパーで自然に途切れ、所々で太る
3. **デジタル系の後処理追加** — 実物観察に基づき (a) マクロ島 + メソ斑の2スケール構造、(b) 境界ディザ（隣接異色セルへの確率スワップでギザギザ食い込み）、(c) 境界近傍限定のスペックル（1セル飛び地、低周波マスクで密度ムラ）
4. **デジタル系のパターン別差別化** — 実系譜（CADPAT→MARPAT→AOR/UCP は同族）どおり共通エンジンだが、面積比・マクロ/メソ周波数・伸長方向（UCP は横伸長）・スペックル色ペアをパターン別に定義
5. **マルチカム/OCP をスコープアウト** — グラデーション地の再現精度が低いため一旦除外。フェーズ2以降で再挑戦

参考実装調査: [CAMO](https://github.com/ecsplendid/CAMO)（fBm 閾値方式、現行実装と同系）、[camogen](https://github.com/glederrey/camogen)（ポリゴン再帰分割 + color bleed 方式。有機系の代替アプローチとして候補）

## v3: 自己改善ループ（10周）

実物参照画像（Wikimedia の布地写真・スウォッチ: M81 / MARPAT / UCP / AOR1 / AOR2）を取得し、
「レンダ → 参照と目視比較 → 採点 → 調整」を10周実施。主な技術的成果:

- **勾配正規化の等高線バンド**（M81黒・ツイッグ共通）: `|field−level| < |∇field|×widthPx` で枝の太さをピクセル単位制御。ノイズ勾配の暴れによる巨大な瘤・マーブル化を解消
- **勾配マスク**: 極値近傍（勾配小）を除外し、等高線由来の「閉ループ（輪っか）」を抑制。分位0.15。強すぎる(0.35)と枝が破線化するトレードオフあり
- **ツイッグシステム**: AOR2/MARPAT 特有の蛇行する暗色細枝。伸長付き等高線バンドをセル量子化
- **粒度の実物合わせ**: デジタル系は当初の3〜4倍細かい粒度が正解（AOR系は特に細粒）。UCP はセル大きめ(cell 5)+横伸長
- **面積比・パレットの実物準拠化**

### 90点未到達の要因分析

実物迷彩は「デザイナーが意図配置した固定図案」であり、統計的手続き生成との残差は:
1. **形状の意図性** — M81 の個々の斑・黒枝は手描きデザイン。確率的生成では「らしさ」は出るが「同じ設計言語」にならない
2. **図案の全体構成** — 実物は視距離設計(近距離ディテール+遠距離ブロブ)が計算されている

90+ に届く候補: ①実物図案の統計(斑サイズ分布・隣接頻度)をフィッティングする最適化 ②実パターンのトレース素材をタイル+変形合成 ③拡散モデル等のML。いずれもフェーズ2以降の大きな投資判断。

## v7: Image Quilting によるウッドランド突破

既存実装調査（Substance Designer / Blender のカモフラ生成レシピ）の結論: プロツールの定番も「ノイズ→閾値→歪み(Warp/Slope Blur/Distortion)」系で、当プロジェクトが到達済みの手法族。この族では M81 の「デザインされた図案感」に限界（~75点）。

**採用手法: Image Quilting (Efros & Freeman, SIGGRAPH 2001)**
- Wikipedia の US Woodland ベクタ画像（米政府図案=パブリックドメイン）を 4値インデックスマップ化し RLE 埋め込み（25KB）
- ブロック(ソース基準 ~200px)をオーバーラップ付きで配置。候補36個から「オーバーラップ不一致(正規化) + 色多様性ペナルティ(黒欠乏を重罰)」最小を選択、境界は動的計画法の最小誤差シームで縫合
- ミラー(H/V)で配置バリエーション増加。シードで全配置が決定的に変化
- **局所形状が実物の設計言語そのもの**のため、斑の指状突起・黒枝の鹿角形状が原理的に再現される
- 失敗と対策: 単純な誤差最小化は「平坦ブロック同士のマッチ」に退化 → ブロック色構成を実物面積比に近づける多様性ペナルティで解消

自己評価（ユーザー較正スケール）: **M81 クイルト 85**。512生成 ~60ms、2048 ~300ms。
プリセットは「従来 / 新手法(形状文法) / 新手法(クイルト)」の3方式並置。

制約・今後: ①ソース由来のため「US Woodland 風」専用（汎用形状生成ではない）②大伸長時は nearest サンプリングのエッジ段差（要スムージング）③同手法は AOR2(SVGソースあり)・UCP にも展開可能。

### v8: ブロブパッチ合成への全面変更

矩形グリッド quilting はユーザーレビューで「ブロックの組み合わせ感・カクカク」と指摘。直線シームは平坦色領域の不一致部で必ず露出する構造的問題（ドメインワープでの隠蔽は櫛歯化・帯状化で失敗）。

→ **ブロブパッチ合成**（Graphcut Textures の簡略版）に変更:
- ベースを全面ランダムクロップで敷き、その上に**有機輪郭パッチ**（角度ノイズで半径変調した星型マスク、r(θ) = R·(0.62+0.55·fbm(θ周期))）を貼り重ねる
- パッチ候補48個から「境界リング上の不一致 + キャンバス全体の不足色を動的補正する多様性ペナルティ」最小を選択
- ミスマッチ境界も**有機曲線の新たな迷彩境界**として自然に見える（直線・矩形が構造的に存在しない）
- ミラーは座標折返し(reflect)でソース範囲外も安全に参照

自己評価: M81 ブロブパッチ **85**（丸み・図案言語・配色バランス、3シード+scale1.3確認）。512生成 380〜600ms。

### v9: 広範囲ソース + 仕上げループ（8周）

1. **ベンチマーク/ソース交換** — Commons の広範囲 M81 スウォッチ（800×685、旧ベクタの約2倍の視野）に交換。ベンチマーク表示・クイルトソース・既定パレット（#9c8f6f/#4c5f49/#5f5345/#3a3e3d）・面積比（24/27/33/16）を同一画像から導出し、生成と参照の見かけスケールを一致させた
2. **鏡映アーティファクト修正** — reflect折返しがパッチ内に入ると蝶々状の左右対称が出る → パッチ中心相対サンプリング + 折返し不要なソース範囲選択に変更
3. **微小フラグメント除去** — パッチ境界が生む実物に無い小欠片（<110px相当）を近傍多数色へ併合。初回実装は BFS 早期打切りで偽成分を量産するバグ → 完全走査に修正
4. **パッチ大型化**（R 150→185/k、被覆2.2x）— 長い黒枝ネットワークが切断されず保存

検証: 4シード × scale 0.7/1.0/1.3/1.55。自己評価（ユーザー較正）: **M81 クイルト 90**。512生成 170〜340ms。
→ ユーザー評価 **88**。残指摘: 縮尺変更時にパッチ境界で色が急変する箇所。

### v10: 境界露出・鏡映の根絶

1. **境界リング誤差の重み強化**（score = ring×2.6 + diversity×1.2、候補60）+ リング誤差 >0.30 ならパッチ中心を再抽選（最大3回）— 「貼っても境界線が出ない場所」を探してから貼る
2. **ベース層の廃止** — 高スケール時にベース敷きがソース折返しを強制し鏡映模様が出ていた → 未塗布センチネル(255)から全面をパッチのみで被覆。境界リング誤差は塗布済みセルのみで評価
3. **ホール充填** — 未塗布残りはその位置中心の追加パッチで充填（未塗布セルのみ上書き）

検証: seed 680219(ユーザー再現)/1234/777/211025 × scale 1.0/1.3/1.8 — 境界急変・鏡映とも解消。512生成 320ms〜1.2s(高スケール時)。
→ ユーザー再指摘: シェイプがパッチ縁で「バサッと」切断される箇所が残存（scale 1.5 で顕著）。

### v11: 領域成長型シーム（切断面の構造的排除）

リング誤差最小化では「シェイプの途中切断」を完全には防げない（続きの無い切り口が円弧/直線として残る）。
→ パッチ貼付を **領域成長型シーム** に変更:
- コア(0.55R)のみ無条件貼付し、そこから BFS で外側へ拡張
- 拡張できる条件は「新値=旧値（継ぎ目不可視）」「新値=隣接塗布済み新値（新シェイプ自身の連続）」「未塗布」のみ
- → 色の遷移が必ず**どちらかの画像の実シェイプ輪郭上**で起こる。切断面が構造的に発生しない（グラフカットの単純化に相当）

検証: seed 1234×scale1.5(ユーザー再現) / 680219×1.8 / 777×1.0 / 211025×1.3 — 切断面消滅。

### v12: 外部レビュー(Gemini)の切り分けと反映

- **不採用(前提誤解)**: fBm多重化・ベクターディスプレイスメント・色別ノイズスケール・シャープ閾値の提案 — 全て「従来手法」で実装済みの手法族で、当プロジェクトで上限(ユーザー評価60)を実証済み。現行クイルトはノイズ生成ではなく実物図案サンプリングのため適用対象外
- **採用(観察は正しい)**:
  1. 「滑らかすぎ/描かれた感」→ 実原因は仕上げ多数決フィルタがソース由来の微細輪郭を削っていた。平滑化をスケール条件付き最小限に(k≈1では無加工)
  2. 「塊サイズ均一」→ 実原因は多様性ペナルティが「全色入り中庸ブロック」を優遇。パッチ径分散を拡大(0.7〜1.3R)し、25%を「マクロパッチ」(1.6〜2.1R・多様性緩和)として実物の大判掃引領域を導入
- 付随修正: ホール充填も候補選択+領域成長型に統一(充填部の切断面を排除)

### v13: 直線的境目・チェッカー模様の解消

ユーザー指摘(scale 2): ①緑/茶の境目が直線的・機械的 ②市松状ノイズ。

- **①の根因 = 半径クリップ**: 領域成長シームは新シェイプの続きを塗るが、ブロブ半径で成長を打ち切っていたため、大きなシェイプが半径の滑らかな弧で切り落とされていた → 「新シェイプの連続」はパッチ半径を超えて自然な輪郭まで成長を許可(bbox 1.9R 上限、コアは0.45Rに縮小)。ブロブ外では「一致 or 連続」のみ塗布
- **②の根因 = 縮小エイリアス**: scale≥1.5 で k>1.4 の nearest サンプリングが細部を市松状に破壊 → **多数決ミップマップ**(2×2の4値多数決で段階縮小、k∈[0.7,1.4] になるレベルからサンプル)

検証: 1234×2.0(ユーザー再現) / 1234×1.5 / 777×1.0 — 両症状消滅。

### v14: 高スケール時の微小点除去

フラグメント除去閾値がスケール反比例(110/scale²)のため、scale>2 で閾値が~20px²まで縮み微小点が残存 → 画面基準の絶対下限 `max(70, 110/scale²)`(512基準px²)を導入。scale≤1 は挙動不変。検証: 1234×2.35(ユーザー再現)で点消滅、777×1.0 で回帰なし(出力バイト一致)。

## v15: プリセット統一 + AOR クイルト化（フェーズ1 精度確定版）

## v15: シームレスタイリング（フェーズ3、2026-09-03）

### 目的

生地印刷・3D テクスチャ用途の前提として、出力を上下左右に並べても継ぎ目が見えないトーラス生成を全手法に導入する。`generate(key, w, h, seed, scale, { tileable })`、既定 `true`。`tileable: false` はフェーズ1 と完全同一の出力（全 6 プリセットのハッシュ一致を確認）。

### 実装

- **共通**: `wrapI`（座標のトーラス折返し）/ `wrapD`（最短差分）を追加
- **クラスタ成長（MARPAT / UCP）**: `growCluster` の近傍 push・同色近傍カウント・ドリフト方向と重心更新を最短差分で計算。境界ディザ・スペックルは全セルを対象にラップ近傍で処理。セル数を `round(w/cellPx)` にして端の半端セルを排除（セル幅は最大 ±1px 不均一になるが境界は揃う）
- **クイルト（M81 / AOR1 / AOR2）**: キャンバスをトーラスとして扱う。候補スコアリングの境界リング・穴埋め・多数決フィルタ・フラグメント除去をすべてラップ近傍で処理。ソース参照は非ラップの相対座標のまま（鏡映対策を維持）
- **`pasteBlobTorus`**: トーラス専用の貼付ルーチンを分離。2 点が重要:
  1. 訪問管理をパッチローカル座標ではなく **キャンバス座標**で行う。M81 のパッチ半径はキャンバス幅の最大 0.8 倍あり、トーラス上で自分自身と重なる。ローカル管理だと同一ピクセルを 2 つの相対座標から別サンプルで塗ろうとし、成長条件が「不一致」判定になって前線が止まり、継ぎ目が直線の切断面になった
  2. 座標丸めは `Math.floor`。`|0` は負側で 0 方向に切り捨てるため x=0 の列が 2 重サンプルになる（同じく成長停止の原因）

### 検証

- 継ぎ目指標: 右端→左端 / 下端→上端 の色変化率 ÷ 内部の隣接変化率（1.0 なら継ぎ目は内部と区別不能）。成長系はセルグリッド単位で測る（ピクセル単位だと cellPx 倍に膨れる）。1 列の指標は分散が大きいので 3 シード平均で判定
- 結果（512×512、scale 1.0、3 シード平均）: 全プリセット 0.6〜1.8。`tileable:false` の woodland は 3 超（指標の妥当性確認）
- 目視: `node tools/render.mjs <out> <seed> <scale> --tile` の 2×2 タイル 6 種 × 複数シード・スケール（0.7 / 1.0 / 1.5 / 2.0）で継ぎ目視認不可。既知アーティファクト（ブロック感・切断面・鏡映・市松・微小点）の再発なし
- 回帰: `tests/tiling.test.ts`（継ぎ目指標）、`tests/determinism.test.ts`（スナップショット更新済）

### 観察: 小キャンバスでのブロブ境界切断（tiling 固有ではない）

384×320 seed 777 で継ぎ目指標 4.4 が出た。原因を追うと、パッチ 4 のブロブ輪郭（半径 138 の円弧）が偶然 x=384 の継ぎ目に乗っていた。円弧は 34 行で 1px しかずれず直線に見える。これはトーラス処理の不備ではなく、クイルト方式が元から持つ「ブロブ境界で新シェイプの成長が止まる → 輪郭が円弧で切れる」性質が、小キャンバス（パッチ 5 個、境界リング誤差 0.4〜0.5 で 0.30 の閾値に届かない）で目立ったもの。512 以上では発生していない。

対策候補（未実施、必要なら Issue 化）: ブロブ半径外でも `nv === v`（同一シェイプの続き）の間だけ 1.25R まで成長を許す「シェイプ完走」。出力の最小サイズを 512 に制限する方が単純。

### 性能

トーラス化による生成時間の増加はほぼ無し（woodland 512: 約 0.8s、1024: 約 3.5s。フェーズ1 と同等）。`pasteBlobTorus` の共有訪問バッファは w×h バイト 1 本。

## v16: 高解像度時の多数決フィルタ（フェーズ4、2026-09-03）

### 問題

woodland 4096×4096 の生成が 10 分以上かかっていた（AOR2 は 41 秒）。原因は有機系の拡大時平滑化 `modeFilter` の半径:
`round(0.8/k × (w/512))`。`k = kBase × (512/w) × scale` に既に `512/w` が入っているため二重スケールになり、
4096px で半径 54（近傍 約 9,000 px × 1,670 万 px）、8192px では半径 216 になっていた。

### 対策

1. **半径式を `round(1.2/k)`** に変更。nearest サンプリングの階段幅は `1/k` px なので半径はそれに比例させる。
   1024px で 3（旧値と同じ）、2048 で 5、4096 で 10、8192 で 20
2. **`modeFilter` を行スライディング実装に**（O(r²)/px → O(r)/px）。円形カーネルの各行の半幅を前計算し、x を 1 進めるごとに各行で左端 1 px を減らし右端 1 px を足す。結果は素朴実装と完全に同一（縮小側の半径 1 も含めて全スナップショット一致）

### 結果

- woodland 4096²: 10 分超 → **約 46 秒**（AOR2 と同程度。残りはパッチ候補スコアリング・貼付の O(px) 部分）
- 目視: `tools/render.mjs --crop=512` で 2048 / 4096 の中央を等倍確認。半径 7（`0.8/k`）では 8px 階段が残ったため 1.2 に決定
- 256px スナップショット・タイリング指標 いずれも不変
- 512px でも scale < 0.95 の出力は変わる（例: scale 0.7 は k=0.665 で半径 1 → 2）。woodland 512px × scale 0.7 / 0.5 × seed 1234 / 777 / 211025 を目視: 微小欠片の消え過ぎ・輪郭の丸まり過ぎなし。scale 0.5 の斜め直線はブロブ境界の既知挙動（v15 参照）で本変更とは無関係

### 残課題

4096² で約 45 秒、8192² は数分。クイルトのパッチ候補スコアリングと貼付は px 数に比例するため、根本改善には
低解像度で形状を決めて拡大する（index マップの多段解像度化）か WebGL 化が必要。Issue #3 に追記。

## v17: 多段解像度生成と進捗コールバック（フェーズ4、2026-09-03）

### 多段解像度

クイルト系のパッチ候補スコアリング・貼付は出力 px 数に比例するため、v16 後も 4096² で約 46 秒、8192² は数分かかっていた。
ソース図案は 800×685 px なので、出力が大きくても形状の情報量は増えない（どの解像度でも同じソース px を nearest 参照する）。
そこで長辺が `baseMax`（既定 1024）を超える出力は、

1. 長辺 1024 に縮小したキャンバスで形状を決める（`k` は `512/w` を含むので自動的に整合する）
2. index マップを nearest で実寸に拡大
3. 平滑化（半径は実寸の `1.2/kFull`）と欠片除去だけ実寸で行う

| 出力 | v16 | v17 |
|------|-----|-----|
| woodland 2048² | 11.8s | 4.2s |
| woodland 4096² | 46s | 9.3s |
| AOR2 4096² | 41s | 4.4s |
| woodland 8192² | 数分 | 45s |

- 1024 以下は従来と完全同一（テストで確認）。256 スナップショット・512 タイリング指標 不変
- 目視: 4096² の等倍クロップで輪郭の滑らかさは v16 と同等、階段なし
- 継ぎ目: 2048² / 2362×1181 / 3000×2000 で確認。**注意**: nearest 拡大後は内部の隣接変化率が 1/f に落ちるため、
  継ぎ目指標（継ぎ目変化率 ÷ 内部変化率）は f 倍に膨れて見える。多段化した出力の継ぎ目は基準解像度で評価すること
- 残りの時間は拡大 + 多数決フィルタ + 欠片除去（いずれも O(px)）。8192² でさらに縮めるなら欠片除去の連結成分探索を最適化する

### 進捗コールバック

`generate(..., { progress })` で 0..1 を通知（クイルト: パッチ毎 → 0.75、穴埋め 0.8、平滑化 0.92、完了 1。成長: レイヤー毎）。
Worker が 2% 刻みでメインスレッドへ中継し、UI は

- プレビュー: まず長辺 192px の粗い結果を即描画（数十 ms）→ 本プレビュー生成中は左下バッジに進捗 %
- 書き出し: オーバーレイに進捗バー

を表示する。フリーズしたように見える時間を無くすのが目的。

## v18: ブロブ境界の円弧切断の解消（フェーズ4、2026-09-03）

### 問題

ユーザー指摘: AOR1/AOR2 に「半円で削られたような模様」、M81 にも半円状の切れ目が目立つ。

切り分け: 512px 出力は v15 以降のどのコミットでも同一ハッシュ、2048px も v17（多段解像度）以前で同じ円弧が出る。
新規発生ではなく **クイルト方式が元から持つ性質**（v15「観察」節で小キャンバス限定として記録した現象が、実際は全サイズで出ていた）。
v17 で高解像度書き出しが実用速度になり、大判で目に付くようになったと推定。

根因は `pasteBlob` の領域成長がブロブ半径 `rad(θ)` で無条件に打ち切られること。半径をまたぐシェイプは
「続きの無い滑らかな弧」で切られる。v13 の記述「新シェイプの連続はパッチ半径を超えて成長を許可（bbox 1.9R）」は
**コードに存在しなかった**（初回コミット時点から半径クリップのまま）。輪郭 `rad(θ)` は角周波数 1.4・2 オクターブでほぼ楕円のため
切れ目が円弧に見え、デジタル系では滑らかな曲線がセル格子を斜めに横切るので一目で分かる。

### 試して捨てた案（同じ轍を踏まないための記録）

1. **半径の外に「完走帯」を設け、半径比 1.45〜1.9 まで同色の続きを伸ばす** — 切れ目が外側の弧に移るだけ。
   ノイズ閾値域で外縁を揺らすと、新パッチの地の色がノイズ形状で止まり、その外に旧色の**帯（C 字・輪）** が残る。
   「どこで止めても、その形の切れ目や帯が残る」ことが本質
2. **内側輪郭を高周波ローブ化**（角周波数 3.0・3 オクターブ） — 隣接パッチの輪郭が小半径で交差し、細い C 字帯が増えた。据え置き
3. 完走に「同色域の通過」を許す — 面積の大きい色（緑/茶の地）だけが遠くまで伸び、サンド比が 0.24 → 0.17 に落ちる

### 対策（`pasteBlob` を統合。非ラップ版とトーラス版 `pasteBlobTorus` は 1 本化、訪問管理は常にキャンバス座標）

半径をまたいで続く新シェイプ（外側の旧色と不一致 = 切れ目候補）を **シェイプ単位で二択** にし、途中で止めない:

- **完走**: 半径の外でも同色（`nv === v`）の続きを自然な輪郭まで塗り足す。上書きできる旧色はまたいだ地点で下にあった色と未塗布のみ、
  旧の同色に達したら合流 → 遷移は新シェイプの実輪郭か旧シェイプの実輪郭に乗る。半径比 `OUT_HI = 2.2`・成長箱・ソース範囲外
  （折返し鏡映になる）に達したら「続きが長すぎる」として完走を取り消し撤回へ
- **撤回**: そのシェイプを内側も含めて塗る前の状態に戻す（`oldBuf`）。境界は新シェイプの実輪郭上に移る。
  撤回した地の中に孤立した新シェイプ（撤回域にしか接しない島）も戻す。残すと旧内容の上に新パッチの図柄（黒枝など）が重なり、
  図柄だけが蓄積して黒比が 0.23 まで上がった
- **選択は色の不足度**: 完走は面積の大きい色を優遇（塗り足す面積 = 新シェイプ ∩ 旧色）、撤回は図柄を蓄積する。
  現況が目標比を 2% 以上下回る色だけ完走、それ以外は撤回（閾値 −0.05 / −0.02 / 0 / +0.02 を比較、+0.02 が最も目標に近い）

付随:

- **パッチ半径の上限 `0.42·min(w,h)`**: 輪郭最大 1.17·bR が短辺の半分を超えるとトーラス上でパッチが自分自身と重なり、
  同じピクセルへ 2 方向から別内容の前線が到達する。両前線の出会う線がパッチ中心の対蹠点を通る**直線の切断面**になる。
  旧実装から存在していたが、撤回で旧内容が残るようになり露出が増えた。トーラス時の成長箱もキャンバス半分に制限
  （M81 512px の 1.6〜2.1R マクロパッチは 215px に丸まる。1024 基準キャンバス以上では影響なし）
- **デジタル系のセル量子化**: `organic: false` はマスク判定座標をキャンバス絶対格子（`cellSrc / km` px、AOR は `cellSrc: 10`）の
  セル中心に丸め、未塗布や合流に接する残りの輪郭も階段状にする。AOR ソースは 960px ベクタ由来で厳密な格子を持たない
  （遷移位置は非周期）ため位相一致は狙わない
- 候補スコアリング・コア走査・ソース参照範囲 `pick(bbIn·km)` は内側半径の箱 `bbIn` 基準（成長箱 `bb` を渡すと
  ソース中央に固定され全パッチが同じ図案になる。試作で踏んだ）
- `tileable: false` の出力も変わる（v15 の「フェーズ1 と完全同一」は v18 で終了）

### 検証

- 目視: seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0 の woodland / aor1 / aor2、2048² の woodland / aor1（等倍クロップ含む）。
  半円状の切れ目・輪状の帯・直線の切断面いずれも消滅。既知アーティファクト（ブロック感・境界急変・鏡映・市松・微小点）再発なし。
  AOR2 の縦筋・AOR1 の横筋は旧出力にも同程度あるソース由来の方向性
- タイル 2×2（seed 777、3 プリセット）で継ぎ目視認不可。`tests/tiling.test.ts` の継ぎ目指標は変更なしで全プリセット合格
- 面積比（512px、3 シード）: woodland サンド 0.25〜0.29 / 緑 0.26〜0.27 / 茶 0.30〜0.35 / 黒 0.135〜0.20
  （目標 0.24 / 0.27 / 0.333 / 0.157。旧 0.18〜0.27 / 0.21〜0.39 / 0.20〜0.48 / 0.12〜0.17 より分散が小さい）。
  AOR1 最暗色 0.027〜0.029（旧 0.012〜0.019、目標 0.041）に改善
- 性能: 512px woodland 1.1〜1.2s（旧 1.0s）、scale 2 で 2.0〜2.8s（旧 2.9〜3.2s）、4096² woodland 10.2s（v17 9.3s）・aor1 5.6s（v17 4.4s）
- スナップショット（256px ハッシュ・多段化経路）はクイルト 3 種が変化。意図した変更として更新

### 残課題

- woodland のサンド比は目標より 0.01〜0.05 高め。完走 / 撤回の閾値は 512px 3 シードで合わせたもので、色ごとの重み付けは未検討
- 撤回で旧内容が残るため、初期パッチの図柄が最終出力に残りやすい（被覆 2.2 倍の前提が弱まる）。被覆係数の見直し余地

## v19: 3 カラーデザート（DCU）プリセットの追加（Issue #23、2026-09-03）

### 目的

米軍 3 カラーデザート（DCU、通称コーヒーステイン）を追加する。実物の特徴は「ライトタン地にペールグリーンと
ブラウンの大きく丸いブロブ」「輪郭の入り組みが少ない」「ブラウンは細いリボン状で面積が小さい」。

### 専用ソース図案を新規生成（m81 は流用しない）

クイルトは「局所形状 = ソース図案そのもの」なので、ブロブの丸みや輪郭の入り組み方はパラメータでは変えられない。
M81 の 4 値マップをブラウンへマージしても黒枝の入り組んだ輪郭が残り、DCU の設計言語とは正反対になる。
加えて `tests/determinism.test.ts` が `max(index) < colors.length` を検証するため、3 色プリセットで 4 値ソースは使えない。

- `tools/gen-src.mjs`（新規）: 参照画像 → N 値インデックスマップ（RLE + base64）の生成ツール。
  量子化はパレット抽出と同じ固定シード k-means（`src/core/kmeans.js`）なので同じ画像なら常に同じソースになる。
  値は**明度降順**（0 = 最も明るい色）で `PRESETS.colors` の並びと一致させる。面積 16px 未満の連結成分は近傍多数色へ吸収する
  （ソースにノイズが残ると全候補の境界リング誤差が底上げされ、「継ぎ目の出ない中心」を選べなくなる）
- `src/core/dcusrc.js`（生成物、base64 17.9KB / ファイル 18KB）: `node tools/gen-src.mjs refs/dcu.png src/core/dcusrc.js 3 DCU`。
  m81src（24KB）と同等なので `camo.js` から静的 import する（`digsrc.js` 280KB の動的 import 制約には該当しない）
- 出典は `refs/dcu.png`（Wikimedia Commons "DCU camo swatch.png"、U.S. Army、パブリックドメイン）。800×800 のフラット 3 色スウォッチで
  k=3 の量子化がほぼ無損失。ソース図案の面積比は実測 0.401 / 0.506 / 0.093

### パラメータの根拠

- `kBase: 1.35` — DCU のブロブは M81 より大きいが、スウォッチ上では M81 スウォッチの形状の約 2.5 倍に写っている。
  等倍参照すると 512px 出力にブロブが 2〜3 個しか入らないため 1/1.35 に縮小参照する。
  多数決ミップマップの発動域（`k > 1.4`）を避けられる上限でもあり、輪郭の階段化が出ない
- `patchR: 150` — ブロブの大きさはソース側で決まるので patchR は継ぎ目の頻度だけを決める。M81（185）より**小さく**した理由は
  トーラス上の切断面（v18「パッチ半径の上限」）: `patchR 230` ではブロブ半径が `bRcap = 0.42·短辺` に張り付き、完走帯（`OUT_HI` 倍）が
  キャンバス一周を超えてパッチが自分自身と重なる。`tests/tiling.test.ts` の縦継ぎ目指標が内部の 3.23 倍（閾値 1.8）に悪化した。
  8 シード（1234 / 777 / 211025 / 42 / 9999 / 314159 / 2024 / 7）での縦継ぎ目指標の最大値は patchR 140 → 2.78、150 → 1.70、200 → 4.18 で、
  150 が最も頑健。指標は patchR に対して単調でなく（165 で 3.41、200 で 0.52）、切断面の発生自体が確率的であることも確認した
- `frac: [0.401, 0.506, 0.093, 0]` / `divw: [1, 1, 1.8, 1]` — frac はソース図案の実測面積比をそのまま置く。
  ただし DCU では候補スコアが境界リング誤差項に支配され（div 項は最大 0.07 に対し `ring·2.6 ≈ 0.8`）、
  **frac / divw を動かしても出力は 1 ビットも変わらない**（0.401→0.60 まで振っても同一。`mkAllowExtend` の符号が反転しないため）。
  記録として測定値を置き、色比の調整は kBase / patchR で行った
- `colors` — `node tools/extract-palette.mjs refs/dcu.png 3` の実測値 `#e9d1ae` / `#bbb18d` / `#8f590b`
  （gen-src.mjs のフル解像度 k-means は `#e9d1ae` / `#bbb18d` / `#8e5809`。ほぼ一致）

### 検証

- 目視: seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0（512px）、`--compare` で実物と並置、
  `--tile` の 2×2、`--size=2048x2048 --crop=512` の等倍クロップ。既知アーティファクト
  （ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点）の再発なし。scale 2.0（`k = 2.7`、ミップ 1 段）でも
  ブラウンのリボンが破断・点線化せず、scale 0.7 でも `cleanupFragments` に飲まれない
- タイル 2×2（seed 1234）で継ぎ目視認不可。`tests/tiling.test.ts` は閾値変更なしで合格
- 面積比（512px、3 シード）: タン 0.31〜0.41 / グリーン 0.50〜0.58 / ブラウン 0.08〜0.11（ソース実測 0.401 / 0.506 / 0.093）。
  完走がグリーンの地を優遇するためグリーン寄りに振れるが、patchR 150 では測定値に最も近い
- 性能: 512px 1.4〜1.6s（woodland と同等）
- スナップショットは `dcu` の 1 行追加のみ。既存 6 プリセットのハッシュは不変（`camo.js` 共通ロジックに手を入れていない証拠）

### 残課題

- 生成結果はソース実測よりグリーンが 0.05〜0.08 多い。原因は完走 / 撤回の非対称（v18 の残課題と同根）で、
  frac / divw が効かないプリセットでは色比の直接制御手段がない。候補スコアの div 項をリング誤差と同オーダーに正規化する余地がある
- ブラウンのリボンが実物より短く分断されがち（実物は長く連続する）。ソース図案の 800px という解像度と patchR の
  小ささが上限になっている
## v20: ソース参照の異方サンプリングと CCE 風の追加（Issue #25、2026-09-03）

### 目的

フランス軍 CCE（Camouflage Centre-Europe）は M81 ウッドランドの図案を横方向に伸ばした派生で、色構成も
同系統の 4 色。専用ソースマップを作らず、`m81src` を横方向だけ粗く参照して「横長ブロブ」という実物の
最大の特徴を再現する（Issue #25）。

### 実装（`genQuilt` の `P.srcAspect`）

- 多数決ミップマップ直後に `kmX = km / (P.srcAspect ?? 1)`、`kmY = km` を作り、`pick()` の探索スパン・
  `srcIn()`・`srcGet()` を軸別レートに置き換えた。`km` の裸参照はこの 3 箇所から排除した
  （1 箇所でも取り違えると `srcGet` の安全折返しが常用経路に入り、v9〜v10 で潰した鏡映対称が即座に戻る）
- パラメータは `opt` ではなくプリセット側（`P.srcAspect`）に置いた。横伸長は図案そのものの性質であり、
  URL 状態やユーザー操作ではない。既存の `P.aspectX / aspectY`（ノイズ周波数倍率、意味が逆向き）と
  区別するため `srcAspect`（>1 で横に伸びる）と命名した
- 既定 1 のとき `km / 1` はビット単位で `km` と同一、RNG 呼び出し列も不変 → 既存 6 プリセットの
  決定性スナップショット・`progress` スナップショット・タイリング指標はすべて変化なし（先に `srcAspect`
  だけを入れて `pnpm test` 全通過を確認してからプリセットを追加した）
- 拡大階段の平滑化半径は `kFull / srcAspect`（軸別レートの小さい方 = 階段幅を決める側）で判定するよう
  一般化した。x だけ 1/a のレートになると階段幅が `a` 倍に広がるため、等方 `kFull` 基準では取りこぼす
- `quant`（デジタル系のセル量子化）は正方セル前提のため等方 `km` のまま。`organic: false` との併用は未検証

### 試して捨てた案（同じ轍を踏まないための記録）

- **面積保存の √分割**（`kmX = km/√a, kmY = km·√a`）: 両軸の逸脱を √a に抑えられミップマップの想定帯
  [0.7, 1.4] から外れにくいという利点はあるが、縦が 1/√a に縮んで「M81 を横に伸ばした」ではなく
  「M81 より細かい別図案」に見えた。目視比較で棄却。`kmX < km` は縮小方向ではないためエイリアス源に
  ならず（市松は `km > 1.4` の過剰縮小で出る）、y を M81 と同一レートに保つ純 x 伸長で問題は起きなかった
- **`divw` で緑比を持ち上げる**: `patchR: 185`（M81 と同値）では緑比が目標を 0.10 下回ったが、`divw` の
  緑の重みを 1 → 1.6 → 2.2 に上げても出力は 1 ビットも変わらなかった。横伸長で 1 パッチが参照する
  ソース領域が横に狭まり、緑優位の候補自体が存在しないため（重み付けでは解けない）。`patchR` を
  150 に下げて 1.5 倍のパッチ数で混ぜる方向で解決した

### プリセット `cce`

`kind: 'quilt'` / `src: 'm81'` / `srcAspect: 1.5`（Issue の 1.4〜1.6 の中央）/ `kBase: 0.95`（M81 と同値。
実物の図案スケールは M81 と同等）/ `patchR: 150` / `frac: [0.305, 0.254, 0.277, 0.165]`。
パレットと `frac` は参照画像 `refs/cce.png`（Commons、CC0）の実測値で、この画像はフラットな 4 色のみ
（ヒストグラムで一意色 4 個）なので k-means ではなく画素数の直接集計で確定した:
ライトカーキ `#a29275` 30.5% / グリーン `#4f5c40` 25.4% / ブラウン `#614f3d` 27.7% / ブラック `#2d2d2d` 16.5%。
色順は `m81src` のインデックス意味順（サンド系 / 緑 / 茶 / 黒）に合わせている。

### 検証

- 目視: seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0、2048² の等倍クロップ、`--tile` 2×2、
  `--compare`（`refs/cce.png`）。M81 比で明確に横長のブロブになり、鏡映対称・切断面・境界急変・市松・
  微小点・全パッチ同一図案いずれも観測されず。等倍クロップの輪郭も階段なし（平滑化半径の一般化が効いている）
- タイル 2×2 で継ぎ目視認不可。`tests/tiling.test.ts` の継ぎ目指標は `cce` を含む全プリセットで合格
- 面積比（512px、3 シード、目標 0.305 / 0.254 / 0.277 / 0.165）:
  - scale 1.0 → 0.20〜0.31 / 0.25〜0.29 / 0.23〜0.31 / 0.14〜0.23
  - scale 1.5 → 0.29〜0.31 / 0.26〜0.27 / 0.26〜0.28 / 0.17（3 シードでほぼ一定）
  - scale 2.0 → 0.31〜0.34 / 0.25〜0.26 / 0.27〜0.30 / 0.13〜0.17
  - scale 0.7 → 0.19〜0.35 / 0.15〜0.41 / 0.04〜0.42 / 0.09〜0.34（大きく外れる）
- scale 0.7 の分散は woodland と同じ構造的原因（`bRcap` に当たった巨大パッチが 4〜5 枚しか置かれず、
  1 枚の色偏りがそのまま面積比になる。woodland も同シードで茶 0.12 / 緑 0.39）。横伸長で 1 パッチ内の
  色多様性が落ちるぶん cce の方が振れ幅は大きい。既存の残課題（被覆係数 2.2 の見直し）と同根なので
  cce 固有の対処はしていない
- 性能: 512px 1.3〜1.8s（woodland 1.5s と同等）、scale 2.0 で 3.4s、2048² で 5.4s
- スナップショット: 既存 6 プリセットのハッシュは不変、`cce` の 1 エントリのみ追加

### 残課題

- scale 0.7 以下の面積比の振れ（上記。パッチ数の下限を設けるか被覆係数を上げる案は未検証）
- `srcAspect` はデジタル系（`organic: false`）と併用すると `quant` が正方セルのままになる。
  デジタル系の伸長プリセットを追加するときは軸別セルにする必要がある

## v21: CCE の黒を最上層の版にする + パッチの異方楕円化（Issue #25、2026-09-04）

### ユーザー指摘

1. 「黒が緑の領域でクロップされているように見える。実物では黒のレイヤーが一番上に乗っている印象」
2. 「一部で直線状 / 半円状に色が切り替わりすぎる。ウッドランドで試行錯誤した半円状の境界（v18）に似ている」

### 原因 1: 黒がパッチ輪郭に削られる（構造的）

実物の CCE / M81 は色ごとの版を順に刷る網版印刷で、黒は最後の版。だから黒のシェイプは他色の境界に
切られず丸ごと乗る。一方クイルトは全色を同時に持つパッチの合成なので、後から貼るパッチの輪郭が
既存の黒ブロブを削る。とくに v18 の「撤回」で旧内容が戻る箇所では、新パッチの実輪郭が旧い黒を
横切って残す → 「緑に切り抜かれた黒」に見える。パラメータでは直せない（黒だけを特別扱いする経路が無い）。

### 対策 1: `P.topLayer`（最上層の版として刷り直す）

`applyTopLayer()` を追加し、パッチ合成が終わった段階（多段解像度の縮小キャンバス上、後処理の前）で:

1. **下刷りを作る**: 合成結果から `topLayer` 色を消し、非 topLayer の最近傍色で埋める（多点 BFS）。
   実物でも黒の版の下には他色が刷られているので、下刷りが連続するのが自然
2. **ソース図案の黒の連結成分を丸ごと貼る**: 成分単位なので輪郭は実物の黒枝そのもので、途中で切れない。
   キャンバス上の伸長は `kmX` / `kmY` に従うので黒も横長になる

置き場所の選び方（10 候補から最良）: `ringMatch`（ソースでその成分の周囲にあった色 = 実物で黒の下にある色が、
キャンバスの下地にもあるか）を加点、既存の黒との重なりと 8×8 区画の黒密度を減点。
減点が無いと下地一致の良い場所に集中し、黒が固まって残りが素抜けになった（実測で確認）。

面積比は成分を丸ごと貼るため粒度が粗い。目標との差が最小成分の 4 割を切ったら打ち切り、
残り面積の 1.6 倍を超える成分は引き直す（8 回まで、駄目なら最小成分）→ 黒比は 8 シードで 0.167〜0.174（目標 0.165）。

**捨てた案 / 踏んだ罠**:
- 目標面積の 3 割を超える成分は使わない。m81 の黒は枝が繋がった大成分（キャンバス換算 21k px = 目標の半分）を
  含み、1 枚で広い面積を占めて黒が一箇所に固まる
- **ソース画像の縁に接する成分は使わない**。そこで切れているのは図案ではなくスキャンの縁なので、
  丸ごと刷ると直線的な断面がキャンバスに出る（実際に右端に黒い矩形状の縁が出た）
- 同じ成分の反復はタイルで目立つ。収まる候補のうち使用回数が最小のものを採り、上下左右の鏡映も 50% で振る

### 原因 2 と対策 2: パッチも異方楕円にする

x だけソースを粗く参照すると（v20）、**図案の特徴だけが sA 倍に広がりパッチ輪郭は円のまま**になる。
すると「特徴 / パッチ」の比が x 方向だけ崩れ、パッチがほぼ単色になる確率が上がる。単色パッチのシェイプ輪郭は
ブロブ半径そのものなので、滑らかな弧が境界としてそのまま露出する（v18 の半円状の切れ目と同じ見え方）。

→ パッチも x を sA 倍した楕円にした（`rad` は正規化空間 (x/sA, y) の単位円をノイズで変調し、方向ごとの交点距離を返す。
`bbInX` / `bbX` も軸別、`pasteBlob` の箱パラメータを軸別に一般化）。両軸で M81 と同じ幾何比に戻り、
1 パッチが参照するソース面積も M81 と同じになる。副産物として v20 で `patchR` を 150 に落とす原因だった
色多様性の低下も解消し、`patchR` は M81 と同値の 185 に戻した。

- `bRcap` は x 側で決まるので `0.42·min(w/sA, h)`
- パッチ枚数は面積被覆ではなく**枚数**を等方時と揃える（`nPatch` から `/sA` を外した）。面積基準だと
  枚数が 1/sA に減り、色比フィードバック（deficit）の反復が足りずシード間の面積比の振れが大きくなった
  （512px で 9 枚 → 6 枚。緑比が 0.118 まで落ちるシードが出た）
- `srcAspect = 1` では従来の式・箱・枚数をそのまま通す分岐にしてあり、既存 6 プリセットの出力はビット単位で不変

### 継ぎ目指標のバグ修正（`tests/tiling.test.ts`）

y ラップの継ぎ目を**横方向**の内部変化率で正規化していた。横長パターンでは分母が伸長率のぶん縮むため、
継ぎ目が無くても指標が悪化する（CCE で 1.99 > 1.8 の誤検知）。軸を揃えて y は縦隣接で正規化するよう修正。
既存プリセット（等方）の判定は実質変わらない。

### 検証

- 目視: seed 1234 / 777 / 211025 / 2024 × scale 0.7 / 1.0 / 1.5 / 2.0、2048² の等倍クロップ、`--tile` 2×2、`--compare`。
  黒は丸ごとのシェイプとして上に乗り、直線的な断面・滑らかな弧の境界いずれも解消。
  既知アーティファクト（ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点）の再発なし
- 継ぎ目: `tests/tiling.test.ts` は全プリセット合格。8 シードの指標は x 平均 1.03（最大 2.32）/ y 平均 1.49（最大 2.41）。
  最大値が出るシードのタイルを目視したが継ぎ目は視認できない（横長パターンでは内部変化率が小さく指標が振れやすい）
- 面積比（512px、8 シード平均）: 0.261 / 0.273 / 0.297 / 0.169（目標 0.305 / 0.254 / 0.277 / 0.165）。
  黒はほぼ目標どおり（版として刷るので直接制御できる）
- 性能: 512px 1.9〜2.2s（v20 1.5s、最上層パスと楕円化で増加）、2048² 6.1s

### 残課題

- 下刷り（3 色）の面積比はシード間の振れが woodland より大きい（緑 0.195〜0.343、茶 0.197〜0.407）。
  横伸長で 1 パッチ内の色多様性が落ちるのが原因で、枚数を揃えても分散は残る
- `topLayer` は最上層 1 色のみ。M81 本体にも適用すれば同じ改善が入るはずだが、既存出力が変わるため別 Issue とする
- 黒の置き場所は「ソースでの周囲色」との一致で決めており、実物のように「茶の帯に沿って走る」といった
  大域的な流れは持たない

## v22: 1px の筋の除去と M81 への最上層版の適用（Issue #25、2026-09-04）

### ユーザー指摘

1. CCE（seed 1234 / scale 1）に幅 1px の筋が残る箇所がある
2. 現行の「ウッドランド (M81)」にも v21 と同じ「黒がクロップされて見える」問題があるので同じ手当てをしてほしい

### 1px の筋（`cleanupSlivers`）

`k ≈ 1` の領域（512px / scale 1.0 など）では階段もエイリアスも出ないため多数決フィルタを掛けない設計で、
そこだけ 1px の筋が生き残っていた。発生源は 2 つ:

- v21 の最上層パスで黒を消すとき、幅 1〜2px の黒枝の跡が「最近傍の非黒」で埋まり、両側の色が
  1px ずつ残る（消えた黒枝のゴースト）
- パッチ輪郭同士の交差でできる 1px の帯

連結成分としては本体に繋がっているため `cleanupFragments`（面積下限）では落ちない。
そこで有機系の後処理に `cleanupSlivers()` を追加した: 左右（または上下）の隣が互いに同色で自分だけ違う
画素を隣の色に倒す、2 パスの専用フィルタ。多数決フィルタより弱く、1px の筋だけを狙って消す。
デジタル系（`organic: false`）は 1px セルが図案なので対象外。

- 効果（512px、seed 1234 の該当画素数）: CCE 43 → 2、M81 125 → 4、DCU 0 → 0（1024px でも同様）
- 残る数画素は斜め階段の一部で、視認できる筋ではない

### M81（woodland）に `topLayer: 3` を適用

v21 の最上層パスをそのまま有効化した。あわせて成分の面積上限を見直した:

- v21 では「目標面積の 3 割超は使わない」としていたが、M81 の黒は **bbox 充填率 0.25 程度の枝分かれ形状**で、
  大きい成分（キャンバス換算 23.5k px、338×282）ほど画面に広く散る。3 割で切ると長い枝が全部落ち、
  黒が中規模のブロブばかりになって実物の枝分かれの語彙が失われた（`--compare` で明確）
- → 上限を目標面積の 6 割に緩めた。固まりの抑制は密度ペナルティ（8×8 区画）と使用回数の平準化が担う。
  トーラスで自分自身と重ならないサイズ制限（bbox が canvas の 0.9 倍未満）とソース縁に接する成分の除外は据え置き

### 継ぎ目指標の作り直し（`tests/tiling.test.ts`）

v21 で軸を揃えたが、CCE では 8 シード平均が 1.90（閾値 1.8）と外れるシードが残った。原因は分母:
横縞状のパターンでは行あたりの色変化数の分布に**重い尾**があり（黒枝の帯を横切る行は中央値の 5 倍以上）、
平均を分母にすると健全なラップ行が過大評価される。実測（CCE seed 314159）ではラップ行の変化数 75 に対し
内部行は中央値 14 / p90 32 / p99 58 / 最大 91 で、**ラップ行は内部行の分布の中に収まっている**
（タイル 2×2 の目視でも継ぎ目は見えない）。

→ 指標を「ラップ行（列）の変化数 ÷ 内部行（列）の p90」に変更し、閾値 2.5 とした。
全プリセット 8 シードの最大は 2.34（CCE の y）で、非タイル生成（`tileable: false`）は 9.9〜16.7 なので
判別力は落ちていない（旧指標の 3 倍より margin は大きい）。

### 検証

- 目視: woodland を seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0、2048² 等倍クロップ、`--tile` 2×2、
  `--compare`。黒枝が丸ごと乗り、実物の長い枝分かれの語彙が出ている。既知アーティファクト再発なし。
  CCE / DCU も同条件で再確認（DCU は `cleanupSlivers` のみの差分で図案の性格は変わらず）
- 面積比（512px、8 シード平均）: woodland 0.237 / 0.320 / 0.274 / 0.168（目標 0.24 / 0.27 / 0.333 / 0.157）、
  CCE 0.253 / 0.280 / 0.301 / 0.167（目標 0.305 / 0.254 / 0.277 / 0.165）。黒はどちらも目標付近
- スナップショット更新: woodland / cce / dcu（+ progress の woodland 多段ケース）。
  デジタル系クイルト（aor1 / aor2）とクラスタ成長系（marpat / marpat_desert / ucp）は不変

### 残課題

- woodland の緑比が目標より 0.05 高く、茶が 0.06 低い（黒を版として抜いたぶん下刷りの比が動いた）。
  `frac` は実物図案の実測値なので、下刷り側の目標値を別に持つべきかは未検討
- 黒の配置は「ソースでの周囲色」との一致で決めており、実物のような大域的な流れ（茶の帯に沿って走る）は持たない

## v23: 下刷りの埋め方を多数決膨張に変更（平行な細線の根絶、Issue #25、2026-09-04）

### ユーザー指摘

CCE に幅 1〜2px の細線が複数シードで再発。**平行に走る 2〜3 本の線**が 1 枚に 2 箇所出ることもある
（v22 の `cleanupSlivers` では消えていなかった）。

### 原因: 最近傍 BFS が細い黒枝を「回廊」にしていた

v21 の最上層パスは、黒を消してから「非黒の最近傍色を 4 近傍 BFS で伝播」して下刷りを作っていた。
黒枝は幅 1〜3px の細長い構造なので、**枝の内部が回廊になり、枝の端から入った遠くの色が領域の奥まで
1〜2px の筋として伝播する**。M81 の黒枝は数本が平行に走るため、筋も平行に複数本出る。
`cleanupSlivers`（1px 幅のみ）では 2px 幅の筋が残り、そもそも筋を作らない設計にすべきだった。

### 対策: 8 近傍の多数決で 1 層ずつ膨張させる

各スイープで「黒だった画素のうち、確定済みの非黒が 8 近傍にあるもの」を多数決色で埋め、
結果はスイープ後にまとめて反映する（走査順に依存しない = 決定性を維持）。
回廊の壁はその領域自身の色なので、多数決では遠くの色が筋として生き残れない。同数タイは小さい色番号。

### 検証（旧実装との直接比較）

- 縞状領域の検出器（±6px の範囲に色変化が 4 回以上ある画素のクラスタ）で旧実装と比較:
  - 旧（v22）: CCE 512px seed 42 に 85 画素、M81 512px seed 1234 に 61 画素のクラスタ。
    該当箇所を等倍で拡大すると、茶の領域の内部にカーキの細線が **3 本平行**に走っている（ユーザー指摘と同一）
  - 新（v23）: 同条件で 0 画素。同じ座標を拡大しても筋は無く、領域が連続している
- 全条件走査（CCE / M81 / DCU × 512・1024px × scale 0.7 / 1.0 / 1.5 / 2.0 × 6 シード = 144 通り）で
  最大クラスタは CCE 44 / M81 41 / DCU 51 画素。DCU は `topLayer` を使わないので、この規模のクラスタは
  高スケールで模様が細かい領域を拾った検出器側のノイズ（該当箇所を拡大して確認済み、筋は無い）
- 幅 1px の筋（`cleanupSlivers` 前の生の値）は 1024px で 22〜28 画素まで低下。`cleanupSlivers` は
  パッチ輪郭の交差で出る残りを掃除する役割として維持
- 目視: CCE / M81 を seed 1234 / 777 / 42 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0、`--tile`、`--compare`。
  既知アーティファクトの再発なし。面積比・継ぎ目指標も v22 と同水準

## v24: 6 カラーデザート（DBDU / チョコレートチップ）プリセットの追加（Issue #24、2026-09-03）

### 目的

米軍 6 カラーデザート（DBDU、通称チョコレートチップ）を追加する。識別点は「ベースのブロブ層の**内部**に散る、
黒フチ付きの白い小石（チョコチップ）」。ブロブ層自体は DCU と同系の大ぶりで丸い形状。

### 2 層構成: 小石はクイルトでは作れない

小石は数 px〜十数 px の孤立点なので、ソース図案に含めてクイルトを通すと必ず消える:

- 多数決ミップマップ（`k > 1.4` で発動、v13 / v16）で潰れる
- `pasteBlob` の領域成長シームに途中で切られる
- organic 系の `minFrag`（512px で 70〜224px 相当）の `cleanupFragments` に丸ごと食われる

→ **`genQuilt` の平滑化・欠片除去・多段解像度の拡大がすべて終わった後、実寸の index に直接描く**
（`if(P.chips) applyChips(...)` を `return` の直前に 1 行）。この位置でしか 1〜2px 相当の黒縁は成立しない。
`P.chips` を持つプリセットだけ処理が走るので、既存 7 プリセットの index マップは 1 ビットも変わらない
（`tests/chips.test.ts` が「chips を持つのは dbdu だけ」を検証し、決定性スナップショットの差分も `dbdu` の 1 行追加のみ）。

**`genQuilt` の 4 色前提ロジックには一切触っていない**（`cnt4` / `hist` / `cur` / `deficit` の 4 要素走査 /
未塗布センチネル 255 を `out[i] < 4` で判定する箇所 / `modeFilter(…, 4, …)` / `cleanupFragments` の `cnt`）。
6 値マップを `genQuilt` に流すと値 4・5 が「未塗布」と誤判定されて穴埋めループが回り続けるため、
色数の一般化に踏み込むと既存全プリセットに出力変化のリスクが波及する。**将来 5 値以上のソース図案が
本当に必要になった時に独立して行う変更**として切り離した（RLE の 3bit 値化も同様に見送り。
現行の RLE は 1 バイト = `(値 << 6) | ラン長` で値が 2 bit しかない）。

### ブロブ層はパブリックドメインの DCU 図案を共有する（基色 3 色）

DBDU のフラットなスウォッチはパブリックドメインで入手できず、Commons で唯一使える図案が鮮明な画像
（`refs/dbdu.jpg` = File:Six-Color Desert Pattern.jpg）は **CC BY-SA 3.0**。この画像を量子化した
ソースマップをアプリに同梱すると share-alike の派生物になるため、**参照画像は目視比較とパレット実測にのみ使い、
ブロブ層は PD の DCU 図案（`src/core/dcusrc.js`）を `src: 'dcu'` で共有する**方針にした。

結果として **基色は実物の 4 色に対し 3 色**（ライトブラウン / ペールタン / ブラウン）になり、index は 5 値。
色の並びは index 値の順に合わせ、ソース図案の面積比（0.401 / 0.506 / 0.093）のうち**最大面積の値 1 に
ペールタンを割り当てた**（実物は淡色が地になる。値 0 に淡色を置くと茶が支配的な別物に見える）。
実物どおりの 4 基色にするには、PD の 4 色スウォッチを入手するか、CC BY-SA 派生物の同梱を受け入れる必要がある。

### 小石層のアルゴリズム

- **配置はジッタードグリッド**。セル幅を `w/nx` で厳密に割り切るのでトーラス上で格子が連続し、
  タイル境界をまたぐ小石も連続する（ポアソンディスクは棄却サンプリングが走査順に依存し、決定性の担保が難しい）
- ジッタは**セル全域**。footprint をセル内に閉じ込めると格子のリズムが目に見えるため、
  隣セルの小石とはみ出して重なるのを許容する（実物も小石が連なってくっついている）。
  重なりを許すので、配置判定はブロブ層のスナップショット（`index.slice()`）に対して行う
- **形は不定形**: 半径を角度の低次ハーモニクス（周期 2 と 3）で変調する（`pasteBlob` の `rad(θ)` と同じ考え方）。
  真円・楕円だと水玉模様に見えて実物と別物になった
- **黒縁は同心の輪にしない**: 同じ形をひとまわり大きくし、ランダム方向へ半径の 0.2〜0.5 だけずらす。
  実物の黒は小石の全周ではなく片側に寄って三日月状に太く出る
- **黒だけの斑点を 22% 混ぜる**（`blackOnly`）。実物には白を伴わない黒い斑点がある
- 大きさは 0.45〜1.55 倍でばらつかせる（実物は大小の差が大きい）
- 乱数はすべてセル座標の `hash2` なので走査順に依存せず、同一シード → 同一配置
- 長さの単位は「512px・scale 1.0」基準 px で、`upx = (w/512)/scale` で実 px に換算する
  （`genQuilt` の `k = kBase·(512/w)·scale` と同じ換算なので、ブロブと小石の寸法比が scale で保たれる）

### パラメータ

`kBase: 1.35` / `patchR: 150` は DCU と同値（`patchR` を上げるとトーラス上の切断面が出るため上げない。v19 参照）。
`chips: {v: 3, rimV: 4, r: 8, rim: 0.42, spacing: 30, density: 0.6, pure: 0.9, blackOnly: 0.22}`。
`colors` は `node tools/extract-palette.mjs refs/dbdu.jpg 8` の実測値から採った
（k=6 では小石の白と地のペールタンが分離しなかったため k=8 で測り、基色 3 + 小石白 + 黒縁を選択）:
`#9a766b` / `#c6b5a4` / `#704c44` / `#e5d5cd` / `#1d1f23`。

### 検証

- 目視: seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0（512px）、`--compare`（実物並置）、
  `--tile`（2×2）、`--size=2048x2048 --crop=512`（等倍クロップ）。既知アーティファクト
  （ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点）の再発なし
- 小石は scale 0.7 / 1.0 / 2.0 のいずれでも消えず、黒縁が 1〜2px 相当で残る。2048px 等倍クロップでも
  縁がぼけず階段化しない（実寸で描いているため）
- タイル 2×2 で継ぎ目視認不可。小石がタイル境界をまたいで連続することを `tests/chips.test.ts` で自動検証
- `tests/tiling.test.ts` は閾値変更なしで合格（小石は内部変化率を上げるので継ぎ目指標は下がる方向）
- 面積比（512px、3 シード）: ライトブラウン 0.29〜0.36 / ペールタン 0.44〜0.51 / ブラウン 0.08〜0.11 /
  小石ホワイト 0.032〜0.041 / 黒縁 0.056〜0.072
- 性能: 512px 1.9〜2.0s（DCU 1.5s に対し小石層の分だけ増える）

### v20〜v23（CCE 側）との統合

Issue #25 の v20〜v23 が先に main へ入ったため、DBDU ブランチは `origin/main` をマージして統合した。
節番号は時系列を保つため DBDU 側を v20 → **v24** に繰り下げた。

- **小石層は v20〜v23 の変更と干渉しない**。異方サンプリング（`sA`）・最上層の版・パッチの異方楕円化・

## v25: 陸自迷彩 2 型風（JGSDF Type II）プリセットの追加（Issue #28、2026-09-04）

### 目的

陸上自衛隊 迷彩 2 型（1991〜）を追加する。米軍以外・国産迷彩としての初出。実物の特徴は
「M81 より丸く小ぶりなブロブ」「ブロブの輪郭から小さなローブ（斑点）が多数分岐する二重構造」
「4 色（タン / グリーン / ブラウン / 黒）で、遠目にざらついて見える」。

### 手法の選択: ドット層の追加ではなく専用ソース図案 1 本

Issue の当初案は「ブロブ層 `genQuilt`（小 `patchR`）＋ 座標ハッシュのドット層の 2 層合成」だった。
実際には**ドット層を実装していない**。クイルトは「局所形状 = ソース図案そのもの」なので、
斑点は図案側に最初から含まれており、専用ソース図案 1 本で二重構造がそのまま再現される。
ドット層を別に足すと (a) 図案由来の斑点と重複し、(b) `cleanupFragments` / 多数決ミップとの
相互作用を新たに検証する必要が生じ、(c) Issue #24 のチョコレートチップ小石層と
パラメータ袋の共通化問題を抱え込む。既存手法の範囲で目標の見え方が出たので追加しない。

### リファレンス画像（布地の写真をソースにするための前処理）

`refs/jgsdf2.jpg` — Wikimedia Commons [File:迷彩服2型の迷彩パターン.jpg](https://commons.wikimedia.org/wiki/File:%E8%BF%B7%E5%BD%A9%E6%9C%8D2%E5%9E%8B%E3%81%AE%E8%BF%B7%E5%BD%A9%E3%83%91%E3%82%BF%E3%83%BC%E3%83%B3.jpg)
（1280×960、Crescent moon 撮影、CC BY 3.0）。既存の 7 プリセットと違い**フラットなスウォッチではなく布地の接写写真**で、
そのまま量子化すると 2 つの形で破綻した。対策として `tools/` に前処理オプションを追加した（いずれも既定オフ、
既存の生成物は byte 一致を確認済み）。

1. **織り目（ツイルの斜め筋）が色の分散として効く** → `--blur=SIGMA`（`tools/gen-src.mjs`）。
   原寸 1280px で k=4 量子化すると `#989689 / #747d6a / #5c6251 / #41423a` となり**茶が緑に吸収されて消える**
   （k-means が設計色ではなく明度で切る）。`--resize=800 --blur=1.2` で `#8f8c7f / #60775e / #765450 / #464e46` に収束し、
   RLE のラン数も 117034 → 19494 に減った
2. **周辺減光が最も暗い値へ丸ごと量子化される** → `--flatten=SIGMA`（`tools/gen-src.mjs` / `tools/extract-palette.mjs`、
   実体は `tools/image.mjs` の `flatten()`。強くぼかした自分自身で割って全体平均へ正規化するフラットフィールド補正）。
   補正前は四隅の減光が値 3（黒）に落ち、**黒の面積比が 10.5% → 21.5% に膨らんで**出力の黒が実物より
   はるかに大きな塊になっていた。`--flatten=80` で解消。sigma は 40 / 80 が有効、120 では照明成分の推定が
   図案そのものを含んでしまいパレットが縮退する
3. **輪郭のアンチエイリアスがパレット重心を隣接色へ引く** → `--core[=R]`（`tools/extract-palette.mjs`）。
   斑点が多い図案では素の k-means 重心だと黒が `#464e45`（緑寄り）になり実物と合わない。
   半径 R の近傍が全て同ラベルの画素だけで中央値を取ると `#46444b` になる

生成コマンド:

```bash

`src/core/jgsdf2src.js`（生成物、800×600、base64 23.6KB / ファイル 24KB）は m81src（24KB）と同等なので静的 import。

### パラメータの根拠

- `kBase: 1.1` — ソース図案（800px）を 1/1.1 に縮小参照する。実物と同じ「512px の画面にブロブが 6〜7 個」の
  見え方になる倍率。1 未満（= ソースの拡大参照）にすると最近傍サンプリングで輪郭が階段化するため 1 以上に留める。
  多数決ミップの発動域（`k > 1.4`）にも入らない。当初 640px ソース + `kBase 1.25` で試したが、実物より細かく写り、
  実物のスケールに合わせて `kBase 0.875` にすると階段化した。**ソースの解像度を上げて kBase を 1 以上に保つ**のが正解
- `patchR: 185` — ソースが M81 と同じ 800px なので M81 と同値でパッチ / キャンバス比が揃う。
  `tests/tiling.test.ts`（閾値 1.8、変更なし）に合格
- `frac: [0.240, 0.468, 0.186, 0.105]` — ソース図案の実測面積比（`gen-src.mjs` の出力）
- `divw: [1, 1, 1, 1.6]` — 黒は面積が小さい（10.5%）ので M81（2.4）ほどではないが重みを足す。
  1 のままだと完走が大面積色を優遇する性質（v18 / v19 の残課題と同根）で黒がさらに痩せる
- `colors` — `#8d8b7f` / `#5e775c` / `#74524e` / `#46444b`（上記の実測コマンド）

## v26: デジタル系派生 3 種（CADPAT TW / 07 式 通用迷彩 / EMR）の追加（Issue #30、2026-09-04）

### 目的

`genGrowth`（クラスタ成長）の派生としてデジタル系 3 種を追加する。米国以外のデジタル迷彩の初出。

- **CADPAT TW（カナダ、温帯林）** — MARPAT の原型。緑 3 段 + タンの 4 色
- **07 式 通用迷彩（中国）** — ライトグレー地に緑・茶・黒
- **EMR / デジタルフローラ（ロシア）** — カーキとダークグリーンが同面積で噛み合い、クラスタが縦に伸びる

### 手法: `genGrowth` 本体は一切変えない

Issue の当初案は「EMR の縦異方性のために `genGrowth` へ成長方向のバイアスを追加する」だった。
実際には**追加していない**。`growCluster` は既に `elongX` / `elongY` の両方を受け取り
（`camo.js` の成長スコア `+ (o.elongY ?? 0) * Math.abs(fy) / fd`）、UCP が `elongX: 2.0` で
横長スラブを作っている。EMR は同じ書式で `elongY: 1.8` を渡すだけで縦長クラスタになる。
共通ロジックに触らないので、既存 MARPAT / MARPAT デザート / UCP のハッシュは自動的に不変
（Issue の完了条件「異方性追加の既定値は等方」は `?? 0` の既定で満たされる）。

つまり本プリセット 3 種は `PRESETS` へのパラメータ + 実測パレットの差分のみで構成される。

いずれも布地写真ではなく合成スウォッチなので、v25 で追加した `--flatten`（周辺減光の平坦化）は不要。
`--core=2`（領域内部の中央値）と `--max-edge` を原寸まで上げた実測だけを行った。既定の `--max-edge=256` では
微細なピクセルが混色し、k-means が設計色ではなく明度の階調を返す（CADPAT で `#393e2f / #515b3c / #68734c / #7f8c5b`

node tools/extract-palette.mjs refs/pla07.jpg  4 --max-edge=873  --core=2
node tools/extract-palette.mjs refs/emr.png    4 --max-edge=2320 --core=2
```

`refs/emr.png` は色数がちょうど 4（RLE 的に完全にフラットな合成画像）で、面積比も画素数から直接取れた
（43.28 / 41.50 / 9.61 / 5.60%）。

**`pla07` のブラウンだけは k-means では測れなかった。** 参照画像が JPEG で、茶は細い筆致としてしか出ないため、
リンギングで生じた白 ⇄ 緑の中間灰が「茶」クラスタに大量に吸われ、重心が灰（`#949791`、領域内部の画素が 320 個しかない
= 実体のないクラスタ）へ流れる。k を 6 / 8 に上げても中心はすべて灰軸に乗り、茶が現れない。
筆致内部（近傍 5×5 がすべて `r - b > 15`）の中央値 `#605645` を採った。`r - b` のしきい値を 15 → 30 と
上げても中央値は `#605748` → `#615541` と 3 以内でしか動かず、値は安定している。

| `pla07` | 43.3 / 36.4 / 10.1 / 10.2 | 41.9〜43.6 / 35.4〜36.8 / 10.3〜10.9 / 10.4〜10.8 |

### パラメータの根拠

**共通** — 参照スウォッチのセル寸法は「量子化後の水平ラン長の平均」で測った（設計グリッドに位相が
揃っていないので剰余ヒストグラムでは検出できない）。CADPAT 8.9px/1024 → 512px 出力換算で 4.4px、
07 式 7.9px/873 → 4.7px、EMR は 8px/2320（ラン長 8 が 39% を占める完全なグリッド）→ 1.8px。

- `cadpat`: `cell 4`（MARPAT と同粒度。CADPAT は MARPAT の原型なので当然一致する）。
  MARPAT と違いタン地を持たず**緑 3 段**なので、色 1（ミッドグリーン）の `ratio` を 0.74 と大きく取り、
  地色（ライトグリーン）を最小面積に追い込む。ダークグリーンは MARPAT のブラウンブラック（17%）より
  広い 29% で、細く枝分かれせず塊で連なるので `compact` を上げ `min`/`max` を MARPAT の 1/4 前後に絞った
- `pla07`: `cell 5`（上記実測 4.7px。MARPAT の 4 より粗いという Issue の記述とも一致）。
  黒は緑の内側に落ちるので `eat: [1]`（緑だけを食う）、茶は緑と地の境界を縫うので `eat: [0,1]` かつ
  `drift: 2.6`（細長い筆致にする）。粗いセルでスペックルを強くすると微小点アーティファクトが目立つので
  density は MARPAT より低い 0.03〜0.05
- `emr`: `cell 2`（上記実測 1.8px）。全 3 層に `elongY: 1.8`。2.0 以上にすると縦縞の反復に退化しはじめるため
  1.8 に留め、`drift` を 1.0〜1.2 に下げて（蛇行で縦異方性を崩さない）`min`/`max` の分散で規則性を壊す。
  クラスタは MARPAT の 1/20 程度と極小で、`growSpeckle` の density を 0.10 まで上げて実物の細かいディザ感を出す

### 検証

- 目視: 3 プリセット × seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0（512px）、
  `--compare` で実物と並置、`--tile` の 2×2、`--size=2048x2048 --crop=512` の等倍クロップ。
  既知アーティファクト（ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点）の再発なし
- タイル 2×2（seed 1234）で 3 種とも継ぎ目視認不可。EMR は縦異方性があるが縦方向の周期性も出ていない
- 面積比は上表のとおり seed / scale によらず ±1.5pt 以内で安定
- 性能: 512px あたり cadpat 17〜30ms / pla07 9〜12ms / emr 38〜44ms（`genGrowth` は `genQuilt` より 2 桁速い）
- スナップショットは `cadpat` / `pla07` / `emr` の 3 行追加のみ。既存 9 プリセットのハッシュは不変

### 残課題

- 3 種とも参照スウォッチよりクラスタがやや大きい。`genGrowth` の面積予算方式では
  「多数の小クラスタ」を作ると `growLayer` の `guard`（4000 回）に当たって予算を使い切れなくなるため、
  現状の粒度が下限に近い。さらに細かくするには予算方式そのものの見直しが要る
- 07 式の実物には茶の筆致が右下がりの対角方向に揃う大域的な流れがあるが、`genGrowth` に方向場の概念がないため
  再現していない。`drift` は蛇行の強さであって向きを持たない
- `pla07` のパレットは JPEG スウォッチからの実測なので、ロスレスのスウォッチが手に入れば測り直す価値がある
