# v24: 6 カラーデザート（DBDU / チョコレートチップ）プリセットの追加（Issue #24、2026-09-03）

### 目的

米軍 6 カラーデザート（DBDU、通称チョコレートチップ）を追加する。識別点は「ベースのブロブ層の**内部**に散る、
黒フチ付きの白い小石（チョコチップ）」。ブロブ層自体は DCU と同系の大ぶりで丸い形状。

### 2 層構成: 小石はクイルトでは作れない

小石は数 px〜十数 px の孤立点なので、ソース図案に含めてクイルトを通すと必ず消える:

- 多数決ミップマップ（`k > 1.4` で発動、v13 / v16）で潰れる
- `pasteBlob` の領域成長シームに途中で切られる
- organic 系の `minFrag`（512px で 70〜224px 相当）の `cleanupFragments` に丸ごと食われる

→ **`genQuilt` の平滑化・欠片除去・多段解像度の拡大がすべて終わった後、実寸の index に直接描く**
（`if(P.chips) applyChips(...)` を `return` の直前に 1 行）。この位置でしか 1〜2px 相当の黒縁は成立しない。
`P.chips` を持つプリセットだけ処理が走るので、既存 7 プリセットの index マップは 1 ビットも変わらない
（`tests/chips.test.ts` が「chips を持つのは dbdu だけ」を検証し、決定性スナップショットの差分も `dbdu` の 1 行追加のみ）。

**`genQuilt` の 4 色前提ロジックには一切触っていない**（`cnt4` / `hist` / `cur` / `deficit` の 4 要素走査 /
未塗布センチネル 255 を `out[i] < 4` で判定する箇所 / `modeFilter(…, 4, …)` / `cleanupFragments` の `cnt`）。
6 値マップを `genQuilt` に流すと値 4・5 が「未塗布」と誤判定されて穴埋めループが回り続けるため、
色数の一般化に踏み込むと既存全プリセットに出力変化のリスクが波及する。**将来 5 値以上のソース図案が
本当に必要になった時に独立して行う変更**として切り離した（RLE の 3bit 値化も同様に見送り。
現行の RLE は 1 バイト = `(値 << 6) | ラン長` で値が 2 bit しかない）。

### ブロブ層はパブリックドメインの DCU 図案を共有する（基色 3 色）

DBDU のフラットなスウォッチはパブリックドメインで入手できず、Commons で唯一使える図案が鮮明な画像
（`refs/dbdu.jpg` = File:Six-Color Desert Pattern.jpg）は **CC BY-SA 3.0**。この画像を量子化した
ソースマップをアプリに同梱すると share-alike の派生物になるため、**参照画像は目視比較とパレット実測にのみ使い、
ブロブ層は PD の DCU 図案（`src/core/dcusrc.js`）を `src: 'dcu'` で共有する**方針にした。

結果として **基色は実物の 4 色に対し 3 色**（ライトブラウン / ペールタン / ブラウン）になり、index は 5 値。
色の並びは index 値の順に合わせ、ソース図案の面積比（0.401 / 0.506 / 0.093）のうち**最大面積の値 1 に
ペールタンを割り当てた**（実物は淡色が地になる。値 0 に淡色を置くと茶が支配的な別物に見える）。
実物どおりの 4 基色にするには、PD の 4 色スウォッチを入手するか、CC BY-SA 派生物の同梱を受け入れる必要がある。

### 小石層のアルゴリズム

- **配置はジッタードグリッド**。セル幅を `w/nx` で厳密に割り切るのでトーラス上で格子が連続し、
  タイル境界をまたぐ小石も連続する（ポアソンディスクは棄却サンプリングが走査順に依存し、決定性の担保が難しい）
- ジッタは**セル全域**。footprint をセル内に閉じ込めると格子のリズムが目に見えるため、
  隣セルの小石とはみ出して重なるのを許容する（実物も小石が連なってくっついている）。
  重なりを許すので、配置判定はブロブ層のスナップショット（`index.slice()`）に対して行う
- **形は不定形**: 半径を角度の低次ハーモニクス（周期 2 と 3）で変調する（`pasteBlob` の `rad(θ)` と同じ考え方）。
  真円・楕円だと水玉模様に見えて実物と別物になった
- **黒縁は同心の輪にしない**: 同じ形をひとまわり大きくし、ランダム方向へ半径の 0.2〜0.5 だけずらす。
  実物の黒は小石の全周ではなく片側に寄って三日月状に太く出る
- **黒だけの斑点を 22% 混ぜる**（`blackOnly`）。実物には白を伴わない黒い斑点がある
- 大きさは 0.45〜1.55 倍でばらつかせる（実物は大小の差が大きい）
- 乱数はすべてセル座標の `hash2` なので走査順に依存せず、同一シード → 同一配置
- 長さの単位は「512px・scale 1.0」基準 px で、`upx = (w/512)/scale` で実 px に換算する
  （`genQuilt` の `k = kBase·(512/w)·scale` と同じ換算なので、ブロブと小石の寸法比が scale で保たれる）

### パラメータ

`kBase: 1.35` / `patchR: 150` は DCU と同値（`patchR` を上げるとトーラス上の切断面が出るため上げない。v19 参照）。
`chips: {v: 3, rimV: 4, r: 8, rim: 0.42, spacing: 30, density: 0.6, pure: 0.9, blackOnly: 0.22}`。
`colors` は `node tools/extract-palette.mjs refs/dbdu.jpg 8` の実測値から採った
（k=6 では小石の白と地のペールタンが分離しなかったため k=8 で測り、基色 3 + 小石白 + 黒縁を選択）:
`#9a766b` / `#c6b5a4` / `#704c44` / `#e5d5cd` / `#1d1f23`。

### 検証

- 目視: seed 1234 / 777 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0（512px）、`--compare`（実物並置）、
  `--tile`（2×2）、`--size=2048x2048 --crop=512`（等倍クロップ）。既知アーティファクト
  （ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点）の再発なし
- 小石は scale 0.7 / 1.0 / 2.0 のいずれでも消えず、黒縁が 1〜2px 相当で残る。2048px 等倍クロップでも
  縁がぼけず階段化しない（実寸で描いているため）
- タイル 2×2 で継ぎ目視認不可。小石がタイル境界をまたいで連続することを `tests/chips.test.ts` で自動検証
- `tests/tiling.test.ts` は閾値変更なしで合格（小石は内部変化率を上げるので継ぎ目指標は下がる方向）
- 面積比（512px、3 シード）: ライトブラウン 0.29〜0.36 / ペールタン 0.44〜0.51 / ブラウン 0.08〜0.11 /
  小石ホワイト 0.032〜0.041 / 黒縁 0.056〜0.072
- 性能: 512px 1.9〜2.0s（DCU 1.5s に対し小石層の分だけ増える）

### v20〜v23（CCE 側）との統合

Issue #25 の v20〜v23 が先に main へ入ったため、DBDU ブランチは `origin/main` をマージして統合した。
節番号は時系列を保つため DBDU 側を v20 → **v24** に繰り下げた。

- **小石層は v20〜v23 の変更と干渉しない**。異方サンプリング（`sA`）・最上層の版・パッチの異方楕円化・
  下刷りの多数決膨張はいずれもブロブ層（`genQuilt` 本体）の話で、小石層は後処理がすべて終わった後に
  実寸 index へ描くため。両側が同じ位置に関数を追加していたコンフリクトは、`applyChips` 一式と
  `cleanupSlivers` の**両方を残して**解消した
- ただし **DBDU の出力ハッシュは変わった**。v22 の 1px 筋除去（`cleanupSlivers`）と v23 の下刷り膨張が
  ブロブ層に効くため。512px 3 シードの面積比は統合前と小数第 3 位まで一致しており
  （タン 0.29〜0.36 / ペールタン 0.44〜0.51 / ブラウン 0.08〜0.11 / 小石白 0.032〜0.041 / 黒縁 0.056〜0.072）、
  変化は 1px 単位の筋に限られる。`--compare` と `--tile` で目視し、小石・黒縁・継ぎ目に劣化がないことを確認した
- 既存 8 プリセットのハッシュは main と完全一致（スナップショットの差分は `dbdu` の 1 行追加のみ）

### 残課題

- 基色が実物の 4 色に対し 3 色（上記のライセンス上の判断）。PD の 4 色スウォッチが入手できれば
  `tools/gen-src.mjs` で 4 値ソースを作り `src: 'dbdu'` に差し替えられる
- 小石の分布は実物よりやや均一。ジッタードグリッドの 1 セル 1 個という上限が効いており、
  実物にある「数個が固まって並ぶ」局所クラスタは再現できていない
