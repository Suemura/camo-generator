# v21: CCE の黒を最上層の版にする + パッチの異方楕円化（Issue #25、2026-09-04）

### ユーザー指摘

1. 「黒が緑の領域でクロップされているように見える。実物では黒のレイヤーが一番上に乗っている印象」
2. 「一部で直線状 / 半円状に色が切り替わりすぎる。ウッドランドで試行錯誤した半円状の境界（v18）に似ている」

### 原因 1: 黒がパッチ輪郭に削られる（構造的）

実物の CCE / M81 は色ごとの版を順に刷る網版印刷で、黒は最後の版。だから黒のシェイプは他色の境界に
切られず丸ごと乗る。一方クイルトは全色を同時に持つパッチの合成なので、後から貼るパッチの輪郭が
既存の黒ブロブを削る。とくに v18 の「撤回」で旧内容が戻る箇所では、新パッチの実輪郭が旧い黒を
横切って残す → 「緑に切り抜かれた黒」に見える。パラメータでは直せない（黒だけを特別扱いする経路が無い）。

### 対策 1: `P.topLayer`（最上層の版として刷り直す）

`applyTopLayer()` を追加し、パッチ合成が終わった段階（多段解像度の縮小キャンバス上、後処理の前）で:

1. **下刷りを作る**: 合成結果から `topLayer` 色を消し、非 topLayer の最近傍色で埋める（多点 BFS）。
   実物でも黒の版の下には他色が刷られているので、下刷りが連続するのが自然
2. **ソース図案の黒の連結成分を丸ごと貼る**: 成分単位なので輪郭は実物の黒枝そのもので、途中で切れない。
   キャンバス上の伸長は `kmX` / `kmY` に従うので黒も横長になる

置き場所の選び方（10 候補から最良）: `ringMatch`（ソースでその成分の周囲にあった色 = 実物で黒の下にある色が、
キャンバスの下地にもあるか）を加点、既存の黒との重なりと 8×8 区画の黒密度を減点。
減点が無いと下地一致の良い場所に集中し、黒が固まって残りが素抜けになった（実測で確認）。

面積比は成分を丸ごと貼るため粒度が粗い。目標との差が最小成分の 4 割を切ったら打ち切り、
残り面積の 1.6 倍を超える成分は引き直す（8 回まで、駄目なら最小成分）→ 黒比は 8 シードで 0.167〜0.174（目標 0.165）。

**捨てた案 / 踏んだ罠**:
- 目標面積の 3 割を超える成分は使わない。m81 の黒は枝が繋がった大成分（キャンバス換算 21k px = 目標の半分）を
  含み、1 枚で広い面積を占めて黒が一箇所に固まる
- **ソース画像の縁に接する成分は使わない**。そこで切れているのは図案ではなくスキャンの縁なので、
  丸ごと刷ると直線的な断面がキャンバスに出る（実際に右端に黒い矩形状の縁が出た）
- 同じ成分の反復はタイルで目立つ。収まる候補のうち使用回数が最小のものを採り、上下左右の鏡映も 50% で振る

### 原因 2 と対策 2: パッチも異方楕円にする

x だけソースを粗く参照すると（v20）、**図案の特徴だけが sA 倍に広がりパッチ輪郭は円のまま**になる。
すると「特徴 / パッチ」の比が x 方向だけ崩れ、パッチがほぼ単色になる確率が上がる。単色パッチのシェイプ輪郭は
ブロブ半径そのものなので、滑らかな弧が境界としてそのまま露出する（v18 の半円状の切れ目と同じ見え方）。

→ パッチも x を sA 倍した楕円にした（`rad` は正規化空間 (x/sA, y) の単位円をノイズで変調し、方向ごとの交点距離を返す。
`bbInX` / `bbX` も軸別、`pasteBlob` の箱パラメータを軸別に一般化）。両軸で M81 と同じ幾何比に戻り、
1 パッチが参照するソース面積も M81 と同じになる。副産物として v20 で `patchR` を 150 に落とす原因だった
色多様性の低下も解消し、`patchR` は M81 と同値の 185 に戻した。

- `bRcap` は x 側で決まるので `0.42·min(w/sA, h)`
- パッチ枚数は面積被覆ではなく**枚数**を等方時と揃える（`nPatch` から `/sA` を外した）。面積基準だと
  枚数が 1/sA に減り、色比フィードバック（deficit）の反復が足りずシード間の面積比の振れが大きくなった
  （512px で 9 枚 → 6 枚。緑比が 0.118 まで落ちるシードが出た）
- `srcAspect = 1` では従来の式・箱・枚数をそのまま通す分岐にしてあり、既存 6 プリセットの出力はビット単位で不変

### 継ぎ目指標のバグ修正（`tests/tiling.test.ts`）

y ラップの継ぎ目を**横方向**の内部変化率で正規化していた。横長パターンでは分母が伸長率のぶん縮むため、
継ぎ目が無くても指標が悪化する（CCE で 1.99 > 1.8 の誤検知）。軸を揃えて y は縦隣接で正規化するよう修正。
既存プリセット（等方）の判定は実質変わらない。

### 検証

- 目視: seed 1234 / 777 / 211025 / 2024 × scale 0.7 / 1.0 / 1.5 / 2.0、2048² の等倍クロップ、`--tile` 2×2、`--compare`。
  黒は丸ごとのシェイプとして上に乗り、直線的な断面・滑らかな弧の境界いずれも解消。
  既知アーティファクト（ブロック感・境界急変・切断面・鏡映対称・市松ノイズ・微小点）の再発なし
- 継ぎ目: `tests/tiling.test.ts` は全プリセット合格。8 シードの指標は x 平均 1.03（最大 2.32）/ y 平均 1.49（最大 2.41）。
  最大値が出るシードのタイルを目視したが継ぎ目は視認できない（横長パターンでは内部変化率が小さく指標が振れやすい）
- 面積比（512px、8 シード平均）: 0.261 / 0.273 / 0.297 / 0.169（目標 0.305 / 0.254 / 0.277 / 0.165）。
  黒はほぼ目標どおり（版として刷るので直接制御できる）
- 性能: 512px 1.9〜2.2s（v20 1.5s、最上層パスと楕円化で増加）、2048² 6.1s

### 残課題

- 下刷り（3 色）の面積比はシード間の振れが woodland より大きい（緑 0.195〜0.343、茶 0.197〜0.407）。
  横伸長で 1 パッチ内の色多様性が落ちるのが原因で、枚数を揃えても分散は残る
- `topLayer` は最上層 1 色のみ。M81 本体にも適用すれば同じ改善が入るはずだが、既存出力が変わるため別 Issue とする
- 黒の置き場所は「ソースでの周囲色」との一致で決めており、実物のように「茶の帯に沿って走る」といった
  大域的な流れは持たない
