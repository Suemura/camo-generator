# v23: 下刷りの埋め方を多数決膨張に変更（平行な細線の根絶、Issue #25、2026-09-04）

### ユーザー指摘

CCE に幅 1〜2px の細線が複数シードで再発。**平行に走る 2〜3 本の線**が 1 枚に 2 箇所出ることもある
（v22 の `cleanupSlivers` では消えていなかった）。

### 原因: 最近傍 BFS が細い黒枝を「回廊」にしていた

v21 の最上層パスは、黒を消してから「非黒の最近傍色を 4 近傍 BFS で伝播」して下刷りを作っていた。
黒枝は幅 1〜3px の細長い構造なので、**枝の内部が回廊になり、枝の端から入った遠くの色が領域の奥まで
1〜2px の筋として伝播する**。M81 の黒枝は数本が平行に走るため、筋も平行に複数本出る。
`cleanupSlivers`（1px 幅のみ）では 2px 幅の筋が残り、そもそも筋を作らない設計にすべきだった。

### 対策: 8 近傍の多数決で 1 層ずつ膨張させる

各スイープで「黒だった画素のうち、確定済みの非黒が 8 近傍にあるもの」を多数決色で埋め、
結果はスイープ後にまとめて反映する（走査順に依存しない = 決定性を維持）。
回廊の壁はその領域自身の色なので、多数決では遠くの色が筋として生き残れない。同数タイは小さい色番号。

### 検証（旧実装との直接比較）

- 縞状領域の検出器（±6px の範囲に色変化が 4 回以上ある画素のクラスタ）で旧実装と比較:
  - 旧（v22）: CCE 512px seed 42 に 85 画素、M81 512px seed 1234 に 61 画素のクラスタ。
    該当箇所を等倍で拡大すると、茶の領域の内部にカーキの細線が **3 本平行**に走っている（ユーザー指摘と同一）
  - 新（v23）: 同条件で 0 画素。同じ座標を拡大しても筋は無く、領域が連続している
- 全条件走査（CCE / M81 / DCU × 512・1024px × scale 0.7 / 1.0 / 1.5 / 2.0 × 6 シード = 144 通り）で
  最大クラスタは CCE 44 / M81 41 / DCU 51 画素。DCU は `topLayer` を使わないので、この規模のクラスタは
  高スケールで模様が細かい領域を拾った検出器側のノイズ（該当箇所を拡大して確認済み、筋は無い）
- 幅 1px の筋（`cleanupSlivers` 前の生の値）は 1024px で 22〜28 画素まで低下。`cleanupSlivers` は
  パッチ輪郭の交差で出る残りを掃除する役割として維持
- 目視: CCE / M81 を seed 1234 / 777 / 42 / 211025 × scale 0.7 / 1.0 / 1.5 / 2.0、`--tile`、`--compare`。
  既知アーティファクトの再発なし。面積比・継ぎ目指標も v22 と同水準
